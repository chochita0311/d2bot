# Asset owners

Every asset belongs to one of these five owners. A screenshot captured during personal testing can still be a reusable game appearance; actual names, accounts, equipment/stock and bindings define the private boundary.

| Owner | Responsibility and internal organization |
| --- | --- |
| `regions/` | Region-specific terrain, monsters and landmarks. [Arcane](regions/arcane-sanctuary/remastered-ko-1922x1140/README.md) keeps manifests at its variant root, runtime crops in `templates/{navigation,hub,terminal,objective,encounters,hover}/` and replay sources in semantic `references/` groups. Region guides distinguish the small uncalibrated catalogs from runtime/replay banks. |
| `character/` | [Sorceress appearance](character/sorceress/remastered-1922x1140/README.md): marker templates, reviewed `templates/body/`, 21 selected surrounding reference crops and their calibration manifest. Appearance matches do not identify an account or prove every buff effect. |
| `ui/` | Shared HUD, weapon-set, automap, menus, waypoint panels, selection markers, stash/cube panels and camera layout. [UI map](ui/README.md) separates current templates/replay sources from uncalibrated marker examples. The [digit atlas](ui/gem-count-digits/README.md) and generic stash header replace personal stock images in gem observation; header matching establishes stash presence, and the run still selects the gem tab before reading counts. |
| `items/` | [Item map](items/README.md): runtime gem icons and loot labels, generic item appearances, and explicitly retained quality/illustration catalogs. Panel/button appearances belong in `ui/`; personal bag layouts and stock are excluded from reusable crops. |
| `private/` | Personal binding/run reports and historical identity metadata remain ignored and local. It contains no image files after unnecessary personal originals were removed; reusable class, UI and terrain images do not belong here. See the [private owner map](private/README.md). |

The whole-tree cleanup retains 339 shared images and no private images. It removed 40 superseded inputs, nine redundant full buff-sequence raws, one unused junction development capture and 23 unnecessary personal-name/layout/stock sources, consolidated one byte-identical area-title duplicate, and replaced one obsolete full gameplay frame with its exact 120×32 digit-four crop. Required replay fixtures, the 21 selected marker/ES crops and distinct common type/state examples without maintained replacements remain. The 14 retained appearances formerly named with `legacy` now use semantic state names; their pixels and recognition limits are unchanged. Uncalibrated catalog examples grant no runtime approval; absent consumers alone neither prove reuse nor justify keeping an unexplained archive. Removed raw sources retain hashes, state summaries and explicit `source_image_retained=false` metadata where needed for observation history.

Use kebab-case for folders and filenames. Put kind/state inside the contextual owner; omit redundant `town-loop-template`, `town-loop-frame`, act/location and owner-encoded language/size prefixes. Preserve meaningful variants such as `window`, `reviewed`, `full-modal`, `open`, `closed` and `occluded`; include crop dimensions only when needed to distinguish retained button variants. Original filenames, execution IDs, crop boxes and hashes belong in the existing owner manifests/reference notes. An uncalibrated crop's dimensions do not establish its original viewport geometry or compatibility with the reviewed 1922×1140 calibration. Move referenced files with their consumers and keep one canonical image for exact duplicates.

Development recordings, replay output and scratch scripts belong under a bounded task-owned `.tmp/` directory. Promote only needed reference images and provenance before cleanup. Runtime or durable documentation must not depend on a temporary image. Do not delete unreferenced originals solely because the current main has no consumer: first resolve whether they are retained reference evidence or superseded duplicates.
