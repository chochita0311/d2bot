# Arcane 상황 인지 탐색

[FEAT-0013](../plans/feature/feat-0013-arcane-perceptual-navigation.md)은 북→동→남→서 탐색 상태, 화면/HUD/공통 입력 연결과 보관 화면 재생을 구현한다. 2026-10-11 최신 연속 main을 GUI에 연결하고 예전 북쪽 실행기는 제거했다. 현재 우선순위는 북쪽 새 방 왕복이며 실제 네 방향 수용은 미완료다. [현재 실행 안내](summoner-run.md)와 [통합 run](../plans/run/run-20261009-07-summoner-live-integration.md)이 자동 버프/조건부ALT·실제 증거·다음 검증을 소유한다. 아래 실행별 수치와 단일 시전 API는 당시 한정된 증거다.

[최신 실제 실행](../plans/run/run-20261009-07-summoner-live-integration.md#attempt7-끝중앙목표-발판-연결과-텔레포터-구간)은 main의 F2 연속 유지·넓은 조향·전투 ON/OFF를 검증 중이다. 사용자는 남쪽을 벗어나 중앙을 지나 북쪽 갈림길에 도달했다고 확인했고, 실행122는 세 상자 끝 자동 확인→같은 방 중앙 복귀를 연결했다. 당시2프레임 기준이며 이후 보강한 정지 시간의 통과로 소급하지 않는다. 실행127은 일지·룬 발판에 도달했다. 새 정지 기준의 자동 중앙 도착·네 방향 실제 연결·30방 수용은 미완료(수용0방)다. 전체2시 등각 흐름과 현재10시/8시 꺾임은 구분한다. 아래 `ArcaneSearch` 단일 시전 계약은 별도 구현이며 연속 main과 아직 조립되지 않았다. 과거 실행40/46과269개 테스트 기록은 당시 제한 증거다.

연속 main의 `ArcaneRouteGraph`는 같은 ORB 특징을 재사용해 장소96개·특징 참조12개·실패 착지48개까지 기억한다. 일시 대응 미확인 때 과거 장소를 보존하고, .64초 이상 대응이 없으면 별도 국소 좌표계를 시작한다. 좌표계 사이에 가짜 변위/간선을 만들지 않으며 이전 특징 재획득 때 해당 좌표계로 돌아간다. 같은 장소 재획득은 확인된 진입 방향을 유지한다. 직선/모서리/갈림은 현재 착지 후보의 배치 라벨이고 물리 연결 확정이 아니다. 지형 이동이2초 없으면 관측된 대체 발판으로 재조준한다. 원본 화면을 지도에 저장하거나 미처리 프레임 큐를 쌓지 않는다.

남쪽 끝→중앙과 중앙→북쪽 끝은 같은 이동 엔진을 사용하고 목표 판독만 다르다. 중앙 복귀는 실물 웨이포인트·100px 근접을 요구한다. `ArcaneHubObserver`는 지역 `hub-patterns.json`의 두 파란 불꽃과 서로 다른 바닥 문양2개 이상이 같은 위치를 지지해야 native 중심을 반환한다. 캐릭터 효과 주변의 작은 단일 crop은 복귀 근거로 쓰지 않는다. `ArcaneTerminalObserver`는 세 상자 외형·비공선 배치·400px 근접을 요구한다. 두 도착 모두 F2 해제 뒤 최소 `max(0.6초, 참고 시전 시간×2)` 동안 현재 근접과 실제 배경2px 미만 정지를 유지하고 안정 관찰2개 이상을 요구한다. 늦은 이동/미확인/근접 이탈은 확인을 초기화한다. 적 미검출은 빈 끝 근거가 아니다. 한 북쪽 끝 외형만 보정됐다. 일지·주변 룬의 목표 발판 판독은 구현했지만 서모너 생존/처치·아이템 획득과 실제 네 방향 완주는 남아 있다.

## 지형·이동 관찰

[ArcanePathObserver](../../diablo2/runs/summoner/navigation.py)는 native BGR, 명시적 viewport·플레이어 기준점·순번·단조 시각·이동 세대와 `PathSettings`를 받는다. `terrain`에는 지역 manifest 또는 실험 보정값의 BGR 팔레트/Lab 거리를 전달한다. 생략하면 기존 Arcane 팔레트이며 현재 그래픽에 적합하다는 뜻은 아니다. UI를 제외하고 격자당 네 표본, 3×3 격자의 작은 조각 제거/틈 보정과 작은 연결 성분 제외를 적용한다. 색/형태 후보는 벽·층·도달 가능의 확정 판독이 아니다.

발밑 가림 때문에 seed 반경 안의 여러 발판 후보에서 시작한다. 초기 가려진 간격은 seed 반경 이내이며, 이후는 관찰된 발판 연결을 따른다. 최대 step에는 기준점에서 첫 seed까지 거리도 포함한다. 날개 방향·방문 흔적·굴곡을 사용하고 직시 가능한 구간을 합쳐 격자 계단을 실제 굴곡으로 오인하지 않도록 한다. 직사각형 갈림/합류는 참고 구조이며 고정 tick으로 단계를 진행하지 않는다. 계단/다른 연결 성분/가림의 오판은 남아 있다.

`BackgroundMotionObserver`는 발판 ORB 대응과 RANSAC 배경 이동의 수/비율/오차·크기/회전을 검사한다. UI와 캐릭터 주변을 제외한다. 미검출 시 마지막 검증 프레임을 보존해 재획득 때 간격 전체를 비교한다. 상대 이동은 위치 변화 후보이며 시전 애니메이션 종료·안전·보스 처치 증거가 아니다.

## 탐색·입력 연결

[ArcaneSearch](../../diablo2/runs/summoner/search.py)는 move-only 조준→후속 프레임의 바닥/호버 확인→한 번 cast→새 세대 이동 확인과 직업 참고 하한 대기를 수행한다. 배경 대응이 끊기면 이전 커서를 폐기하며 미확인 도착 중 추가 시전을 쌓지 않는다. 호버/입력 횟수·도착/날개/귀환/전체 시간은 명시적 상한을 소비한다. 실패 후 방 재시작은 하지 않는다.

도착에는 누적 이동뿐 아니라 연속 안정 프레임을 요구한다. `SearchLimits.settled_frames`는2 이상 정수, `settled_motion_pixels`는 프레임 간 검증한 배경 이동 길이의 양수 상한(px)이다. 늦은 추가 이동/대응 끊김은 안정 횟수를 초기화하고 도착 시한을 늘리지 않는다. 합성 시험의2프레임/2px는 실게임 보정값이 아니다.

긍정적 빈 끝 뒤 확인된 상대 이동 흔적을 역순으로 현재 화면에 투영한다. 흔적상 중앙에 돌아와도 긍정적 `hub_ready`가 없으면 미세 시전을 반복하지 않고 확인을 기다린다. 확인 뒤에만 다음 날개를 시작한다. 긍정적 `summoner_present`는 전투가 이동을 선점한 중에도 남은 탐색을 취소하고 상위 전투로 인계하며 처치/회수로 기록하지 않는다. 네 날개 모두 빈 끝이면 탐색 이상이다.

아케인 호버는 상자·관·신단·맵 텔레포터다. 커서만 옮긴 뒤 새 프레임에서 해소를 확인한다. **NPC 호버는 마을 전용**이며 `ArcaneScene`은 거부한다.

[ArcaneSearchRuntime](../../diablo2/runs/summoner/search_runtime.py)은 `ScreenCapture`, 같은 프레임 HUD, 명시적 `scene_reader`, 공통 [FieldControlRuntime](field-control.md)을 연결한다. 캡처 시작의 단조 시각을 사용해 HUD/CV 시간까지 나이에 포함한다. 캡처 전후·입력 직전 실제 창 원점/크기를 확인하고 local 조준점을 desktop 좌표로 바꾼다. 창 이동/크기 변경은 종료 사유다.

실제 입력에는 실행 중인 독립 watchdog이 필요하다. `with driver:` 안에서 `run(wait=...)`/`step()`을 호출하고 같은 context에서 Summoner 발견을 상위 전투로 인계할 수 있다. 종료 시 runtime/capture를 정리한다. dry backend는 입력 없는 검증에서 수동 pump를 허용한다.

공통 `navigation_allowed(stamp)`/`dispatch_navigation(stamp, aim=..., cast=...)`는 최신 공통 판단이 travel 상태의 `destination_unconfirmed`일 때만 경로를 허용한다. 같은 actor lock 안에서 버프/회복/전투/전리품/중단/포커스/기한을 재검사하고 유지 키 해제 뒤 최대 한 번 press한다. 선점됐지만 시전하지 않은 요청은 폐기하고 다시 조준한다. 같은 `ArcaneScene`에 다른 held 이동 목표를 넣을 수 없다.

`scene_reader(frame, stamp)`는 그 프레임의 정확한 stamp로 `ArcaneScene`을 반환한다. field/적/정리/전리품, 빈 끝/보스, 중앙 도착, 호버 박스, 현재 native `player_ground`, 선택적 버프 확인의 의미와 실제 검증은 생산자 소유다. live 경로에 `player_ground`가 없으면 `player_ground_unverified`로 보류하며 생성자의 고정 anchor를 대용하지 않는다. dry 검증만 명시적 기준점을 허용한다. 일반 끝 템플릿·중앙 표식 보임·적 미검출을 각각 빈 끝·현재 중앙 도착·안전으로 승격하지 않는다. 실제 생산자/GUI 연결은 후속이다.

현재 `FlashGroundObserver`는 공용 `assets/character/sorceress/remastered-1922x1140/manifest.json`의 청색 플레이어 표식과 ES/몸 외형을 결합한다. 지도 없는 화면은 현재 ES 아래의 몸 템플릿(원본/15px 흐림), 또는 주변과 구별되는 세로 몸 전경을 요구한다. 전경 방식은 템플릿 신뢰 점수를 만들지 않는다. 과거 좌표/고정 화면 중심을 대용하지 않으며 복수 후보는 거부한다. 실제113은126개 기록 관찰에서 이 위치 생산자를 사용했고114는 끝 발판까지 이동했지만,116은 기둥 가림에서 정지했다. 물리 투영·모든 자세/계단·독립 방 정확도는 미검증이다.

현재 GUI는 공용 `assets/ui/layouts/remastered-1922x1140/camera-ground.json`을 새 창/HUD/닫힌벨트/알려진패널/포커스 검사로 활성화한다. 검토 viewport가 유효한 동안 가림을 보완하며 실제 몸 관찰과 투영을 구분한다. 아래 감독 패널 허가/기본2초 투영 설명은 기존 진단 모드의 계약이며 현재 GUI 준비에 감독 JSON이 필요하다는 뜻이 아니다.

사용자가 승인한 `CalibratedCameraGroundObserver`는 연속 main에서만 이를 보완한다. 최신 감독 `panels_closed=true`와 프로그램의 필드 입력 연속성을 전제로, 서로 다른 실제 몸 판독3개·0.15초 이상·중앙값 주변12px 이내에서 카메라 발 위치를 보정한다. 같은 프레임의1922×1140 창/포커스·현재 자원 비율·닫힌 벨트를 요구하며 인벤토리·웨이포인트·메뉴 열림 양성에서 권한을 폐기한다. 모든 사이드 패널을 자동 분류하는 기능은 아니다. 몸 미확인일 때만 마지막 실물 판독 이후 최대2초 투영하고, 추적 표식/투영으로 시한을 연장하지 않는다. 몸 위치24px 초과 이탈·창 변경·HUD 실패·역행 시각은 보정을 폐기하며 복수 후보는 대체하지 않는다. 기록은 실제 위치와 `camera_ground_projection`/보정 시각을 구분한다. main121에서 가림3개 관찰에 소비됐지만 독립 정확도 검증은 아니다.

main120에서 진입 방향이 목표 북쪽과 같은 경우에도 북쪽 출구를 금지하던 결함을 수정했다. 전체 목표로 복귀하는 현재 출구는 진입 방향 회피보다 우선한다. main121은 같은 방의 세 상자 끝에 도달했고45초 개발 interval2개가 자동 연결됐다. 끝 자산은 아이템 이름이 섞인114 crop에서 이름표 없는121 crop으로 교체했고122에서 자동 끝 확인→같은 방 복귀 시작을 관찰했다. 세 상자·근접·정지 양성 직후0.5초 미만의 동일 프로세스 전환에서만 복귀를 시작한다. `--all-wings`는 북쪽 outbound 시작 전용이며 중앙 복귀의 최신0.5초 미만 정지 확인 뒤 동→남→서로 전환한다. 네 곳 모두 세 상자 끝이면 이상 검토로 멈추며 정상 마감으로 세지 않는다. 증거 파일은 날개/출발·복귀/구간 번호로 분리한다. 보스·회수·실제 네 방향·정상 마감과30방 수용은 미완료다.

`field_input_probe --step-after-buff north --seconds 0.1`은 Flash buff/stdin 모드의 별도 제한된 진단이다. `main.py --summoner-run --live --north-casts 8`은 단일 시전 회귀 모드이며 현재 연속 main은 `--continuous-north --field-seconds 60`을 사용한다. 계획기의 일반 연결 모드와 명시적 텔레포트 모드는 별도다. 후자는 현재 발판 내부 여유32px/거리600px 상한으로 넓게 관찰하며, 연속 main은 선호 거리도600px로 둔다. 같은 화면의 중앙 표식이 발 위치220px 이내일 때만 연결 모드의 출발 반경180/step240 보정을 허용한다. 일반 seed 반경은96px다. 단일 시전의 포인터 이동 뒤50ms 처리 시간도250ms 시한에 포함하며, 연속 main은 현재 발판 소실/두 새 꺾임 관찰로 참고 시전 시간 이전에도 조향한다. 느린 계산은 입력하지 않고 새 화면에서 다시 수행한다.

후속1.5초 안에서 새 HUD/표식/배경의 방향·거리와 연속 안정 화면을 확인한다. 확인한 변위만 위치/이동 흔적에 누적하며, 일시적인 표식·발판 가림은 최대2초 동안 입력 없이 재관찰한다. 실패한 계획 화면도 기록한다. 감독 확인은12초 제한 구간 시작 조건이며 매 시전의 최신 화면·중단 조건을 대체하지 않는다. main 실행40은3회 도착을 통과했고 실행46은 네 번째 실제 이동 뒤 HUD 문구/배경 간섭으로 안전 종료했다. 이 제한 증거는 GUI/네 방향 완주를 뜻하지 않는다.

단일 시전 main은 포인터 이동/50ms 대기 뒤 새 HUD와 `ArcaneHoverObserver`의 상자·관·신단·텔레포터 외형을 검사한다. 연속 main은 양성 호버에서 F2를 해제하고 현재 관측 발판으로 커서만 옮긴 뒤 새 화면으로 이동을 다시 판단한다. 자원 미확인/호버 처리도 원래 화면250ms 시한을 늘리지 않는다. NPC는 포함하지 않는다. `evidence_box`는 매치한 외형 박스이며 실제 물체 경계가 아니므로 `ArcaneScene.hover`로 직접 승격하지 않는다. 일반적인 호버 회피·해소의 실게임 검증은 남아 있다. 실행47의 검은 캡처는 이후 실행에서 복구됐으며 HUD v8과 플레이어 몸통 보완의 실제 후속 결과는 최신 run이 소유한다.

12초 제한 구간은 계획 재시도·포인터 후 검사·입력 직전·도착 관찰에 하나의 절대 마감시간을 적용한다. 각 단계의250ms/2초/1.5초 한도가 전체 구간을 연장하지 않는다. 마감시간 뒤 도착 자료는 성공으로 승인하지 않으며 실패 종료로 넘긴다.

## 입력 없는 재생

같은 날개도 방마다 타일 variation과 계단형·텔레포터형의 배치 차이가 있다. 현재 유형 자산은 두 계단 외형뿐이며 모든 유형 분류기를 완성한 상태가 아니다. 회색 외형을 실제 연결로 확정하지 않고, 시전 후 이동/정지와 관측한 출구를 함께 소비한다. 조준 예상 겹침 필터가 실패하면 전체 특징의 기존 RANSAC 조건을 재검사해2px 미만의 실제 정지만 복구한다. 큰 이동은 이 보완으로 승인하지 않는다.132는 한 좌표계 안에서 지형을 다시 찾았지만 중앙에 도착하지 못했다. 이후 실제 통과한 출구 횟수와 시전 중 출구 의도를 경로 선택에 반영했으며 실제 검증 중이다.

일지·룬 목표 판독은 검증한 기존 일지 자산과 현재 주변 큰 파란 룬을 결합한다. outbound의 입력/남은 탐색을 멈추며 귀환에는 적용하지 않는다. 이 목표 발판 후보는 서모너 생존/처치·캐릭터 도착·획득 증거가 아니다.

[재생 도구](../../diablo2/tools/arcane_navigation_replay.py)는 기존 crop을 원본 크기의 viewport에 배치하고 지역 manifest 또는 [명시적 보정 파일](../../assets/regions/arcane-sanctuary/remastered-ko-1922x1140/navigation-calibration.json)을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m diablo2.tools.arcane_navigation_replay --manifest assets/regions/arcane-sanctuary/remastered-ko-1922x1140/manifest.json --calibration assets/regions/arcane-sanctuary/remastered-ko-1922x1140/navigation-calibration.json
```

`--overlays <새 디렉터리>`는 검토 그림을 만들며 기존 디렉터리를 덮어쓰지 않는다. 출력은 `inputs_sent=0`, 출처·후보·배경 대응·CV 시간이며 자동 합격 표시가 아니다. episode/시간이 이어지지 않으면 배경 기준을 초기화한다. JSON 각1MiB, 원본8백만 pixel, 최대100개 장면으로 제한한다.

보정의 지형 팔레트·경로·텔레포트 값은 `load_arcane_step_planner`를 통해 감독 main과 입력 없는 재생에 쓰인다. 고정 사람 기준점 `(961,620)`은 재생의 진단 대용이며 live는 현재 판독 위치를 전달한다. 이 값들은 개발 보정이고 운영 적합성이 검증됐다는 뜻은 아니다. 원본은 북쪽 두 레이아웃뿐이며 동/남/서 검증 자료가 아니다. 실제 네 날개 완주/자동 중앙 귀환/30방 수용은 미완료다.
