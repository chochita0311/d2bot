# 필드 버프 확인과 벨트 닫힘

단계 요청 API인 [BuffSequence](../../diablo2/common/buffing.py)는 캐릭터/방별 개인 입력 순서를 한 단계씩 요청하는 공통 상태 코드다. 게임 입력·캡처를 직접 수행하지 않는다. [필드 검증 기록](../plans/run/run-20261005-04-field-buff-confirmation.md)은 감독 시전과 실제 화면 증거를 소유한다. 기존 아케인 토큰 실행기는 아직 이 확인 계약을 소비하지 않는다.

같은 모듈의 연속 실행기 `BuffSequenceExecutor`는 관찰·입력·시계·중단 가능한 대기를 주입받아 프로필 순서와 키별 간격대로 연속 실행한다. Flash는 `w → a → a → s → F1 → d → w`이며 마지막 `w`는 장비 복귀다. 매 키 사이의 검사는 자동 최신 관찰이고 사람의 확인을 기다리는 단계가 아니다. 적 접근/저자원/고갈/벨트 미닫힘/중단/시간 상한은 남은 입력을 취소한다. 장비 복귀가 불확실한 중단 이후 처리는 소비자가 확인해야 한다.

감독 입력 probe는 공통 실행기와 별도의 시험 도구이며 [유지 입력 run](../plans/run/run-20261005-06-field-control-loop.md)이 실제 전송 간격과 결과를 소유한다. 공통 executor는 주입형 검증에서 프로필 간격과 중단을 확인했으며 실제 scene 생산자 연결은 남아 있다. 연속 전송을 완료해도 실행 결과는 `await_confirmation`, 버프 상태는 `await_effect`이고 효과·장비 복귀 확인이 필요하다.

## 버프 확인 계약

소비자는 최신 `SafetyObservation`, 명시적 화면/벨트 유효 시간, 실제 필드와 주변 적 없음 근거를 전달한다. town·미확인 안전·오래된 관찰·다른 캐릭터/방은 요청을 막고, 회복/종료 판단은 버프보다 먼저 반환한다. 시작한 순서가 중단되면 새 트랜잭션으로 다시 준비한다.

`next_step`의 요청 뒤 `acknowledge_step`은 해당 단계의 전송 결과만 기록한다. 중복 `a`도 별도 단계이며 미확인 입력을 재전송하지 않는다. 전체 입력 이후에도 상태는 `await_effect`다. `BuffConfirmation`은 같은 최신 관찰의 실제 효과, 전체 순서의 효과, 개인 전투 장비 복귀를 모두 명시적으로 확인해야 한다. 출처는 감독 시각 확인 또는 별도로 검증한 시각 판독기다. 타입이나 출처 이름 자체가 시각 근거를 만들어 주지 않는다.

[최대값 증가 후보](../../diablo2/common/buffing_vision.py)는 같은 화면에서 읽힌 생명력·마나 최대값이 모두 늘었는지만 비교한다. 버프 이름이나 다른 효과의 완료를 확정하지 않는다. [공통 I/II 탭](../../assets/ui/weapon-set/README.md)도 활성 세트만 읽으며 개인이 복귀해야 할 세트를 추측하지 않는다. 현재 필드/주변 적 없음과 전체 효과 확인은 감독자가 담당했고 자동 판독기는 없다.

확인된 타이머는 해당 단계 **입력 요청 직전 관찰**의 보수적 시각에서 시작한다. 나중의 전송 완료·효과 검토 시각으로 수명을 늘리지 않는다. 모든 단조 시각과 순번은 같은 생산자/시계 영역에서 생성해야 한다. 별도 Python 프로세스의 `perf_counter` 값을 합쳐 시전 간격을 계산하지 않는다. Flash의 전투 지시는 개인 설정 150초/10초 여유를 사용하며 이번 감독 테스트에서 지속시간을 측정한 것은 아니다. 완료한 트랜잭션도 갱신 필요 시 진행 허가를 반환하지 않는다.

## 벨트 관찰과 이동

`BeltInspection.request_toggle`은 개인 backtick 키를 요청하면서 표시 상태를 미확인으로 바꾼다. 펼친 화면에서 모든 슬롯이 확인돼야 잔량을 갱신한다. 모호한 펼침 자료는 잔량을 무효화한다. 닫힌 한 줄로 숨은 포션 수를 다시 계산하지 않는다.

[HUD 판독기](survival-observation.md)의 `belt_visibility`는 `expanded`, `closed`, `unknown`이다. `closed`에는 별도의 닫힌 벨트 테두리 증거가 필요하다. 닫는 키의 전송 성공이나 펼침 미검출만으로 이동하지 않는다. `permits_movement`는 최신 닫힘과 공통 생존 판단을 요구하며 열림·가림·오래된 닫힘·재버프/회복/종료 필요 시 보류한다. 이는 벨트/생존 조건이며 경로 도착·주변 전투 안전의 독립적인 증거를 대신하지 않는다.

현재 입력 없는 CLI는 프레임마다 독립 관찰하므로 닫힌 벨트에서 과거 잔량을 복원하지 않는다. 이후 런 통합은 동일한 방의 관찰·확인된 소모/획득과 닫힘 상태를 함께 유지해야 한다.
