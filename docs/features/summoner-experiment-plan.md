# 서모너 런 실험 및 데이터 계획

## 상태와 읽는 순서

`2026-10-04` 작성한 **전체 서모너 계획 초안**이다. 아래 표본 수·통과 기준·폴더 배치는 제안이며 실행 스펙을 대신하지 않는다. 이후 사용자가 승인한 마을 방 반복은 [FEAT-0002](../plans/feature/feat-0002-supervised-town-room-loop.md)에서 실행했고, 실제 캡처·입력·결과는 [실행 기록](../plans/run/run-20261004-02-supervised-town-room-loop.md)이 소유한다. 생존·버프·전투·전리품의 실행 승인은 별도다.

| PRD | 소유하는 결과 |
| --- | --- |
| [PRD-0003 방 반복](../plans/prd/prd-0003-summoner-room-lifecycle.md) | 캐릭터 선택→생성→마을→종료→선택 화면, 감독과 입력 권한 |
| [PRD-0004 생존·버프](../plans/prd/prd-0004-summoner-survival-and-buffs.md) | HUD 신뢰도, 회복/탈출, 매 방 버프 확인 |

## 이번에 확인된 사용자 기준

- 대상: **온라인 소프트코어, 기본 Resurrection의 원소술사 Flash, 노바 공격**. 현재 캐릭터를 실험용으로 사망시키지 않는다. ROTW로 확장할 때 경로가 같다는 추정도 별도 검증한다.
- 버프 입력: `w → a → a → s → F1 → d → w`. `a` 두 번은 생략하지 않는다. 마지막 스왑 후 `F2`로 텔레포트, `F4`를 누르고 있으면 노바 공격이다.
- 버프 이름/효과/지속시간, 빠른 시전 설정, 텔레포트 홀드 여부와 안전한 시전 위치는 미확인이다. 단축키를 눌렀다는 사실로 효과를 확정하지 않는다.
- [현재 Flash 설정](../../config/characters/characters.json)은 `…s → d → F1…`이다. 사용자 지시가 우선하며, 이 초안에서는 설정을 수정하지 않았다. 승인된 프로필 정합 작업에서 순서 차이를 해소해야 한다.
- 회수 대상은 증오의 열쇠·이스트 이상 룬·스몰/그랜드 참·유니크 반지/목걸이, 자원 부족 시 필요한 스크롤이다. 참 기준은 [PRD-0007의 초기 규칙](../plans/prd/prd-0007-shared-loot-and-town-maintenance.md#initial-keep-rules)이 소유한다. MF 7%는 단일 옵션도 보관, 저항은 번개/독 11%, 번개 최대 피해는 70 이상, 두 지정 스킬참은 모두 생명력 30 이상이라는 사용자 확인을 반영했다. 자수정·모든 룬·라지참을 기본 회수 목록으로 사용하지 않는다.
- 서모너의 핵심 목표는 빠른 키 파밍이다. 일반 적은 가까이 붙었을 때 필요한 처리만 하며, 전체 청소·먼 적 추격·상자 전부 열기를 기본 범위로 넣지 않는다. 근접 판정은 PRD-0006에서 정의한다.
- 정상 시작·마감은 Act 1. 비상 탈출에서는 Act 1 마감보다 생존을 우선한다.
- 화면 방향: 좌상 10시 / 좌하 8시 / 우하 4시 / 우상 2시. `10→8→4→2`라는 사용자 설명은 방향 배치 자료이며 탐색 우선순위 확정과 구분한다.

## 단계별 실험 제안

공통 순서는 **자료 관찰 → 입력 없는 재생 확인 → 한 번의 감독 입력 → 짧은 반복 → 사람이 결과 확인**이다. 앞 단계의 필요한 결과가 확인되지 않으면 필드 실험을 확대하지 않는다. PRD 승인만으로 모든 단계의 실제 입력이 승인된다고 해석하지 않으며 이후 기능 경계와 실행 예산을 검토한다.

빠른 텔레포트 필드 실험 전에 [PRD-0008](../plans/prd/prd-0008-realtime-runtime-and-recording-retention.md)의 최신 관찰·저장 지연 분리 조건을 검증한다. 100–200회 확대 전에는 게임 입력 없는 장시간 기록 부하, 큐/메모리 포화, 총 디스크 상한·retention·종료 복구를 확인한다. 저장자/GUI 소비가 느려져도 생존 입력이 기록을 기다리지 않아야 한다. 현재 마을 evidence는 이 구조를 구현한 것이 아니다.

| 단계 | 해소할 질문과 선행 조건 | 자료·표본 제안 | 사람이 볼 결과와 다음 경계 |
| --- | --- | --- | --- |
| E0 관찰 기준선 | 현재 창·HUD·키 설정·자료 소유 경계가 맞는가? 실제 입력 없음 | 수동 플레이/기존 자료에서 선택·로딩·마을·HUD·아케인 중앙·메뉴 각각 10개 이상의 서로 다른 장면; 핵심 전환 3회. 위험 자료는 기존 녹화/재생으로만 | 게임 계열/버전·언어·그래픽·해상도·DPI·필터, 캡처 영역, Flash 프로필 차이 확인. 상태별 자료 부족 표시 |
| E1 방 생성·종료 | 전투 없이 마을 범위에서 종료와 재생성이 확인되는가? E0 및 중단 경계 필요 | 1회 감독 후 3회, 이후 총 20회 제안. 느린 로딩/메뉴 오인 등은 재생 또는 안전한 마을 상황 | 잘못된 난이도/캐릭터, 이중 생성, 중단 후 입력 0. 전환 증거 누락 0. 전투 지역 확대 전 안전 검토 |
| E2 생존 관찰·버프 | HUD를 믿을 수 있고 매 방 실제 버프를 확인하는가? E1 필요 | HUD 상태별 20장 이상, 독립 가림/효과 클립; 버프 전후 10방. 물약·탈출은 승인한 안전한 상황에서 1회부터 | 위험/불명확을 정상으로 분류 0. 버프 미확인 출발 0. 비상 입력 선점과 실제 결과 확인. 지연 상한 결정 전 필드 자동 이동 보류 |

| E5A 노바 전투·회수 | 근접 판단과 F4 홀드 중 안전 선점, F2 이후 라벨 재획득이 되는가? E2/E4 필요 | 근접/경계/멀리 있음·가림·텔레포트 전후 정답, 감독 처치 10회. 열쇠 양성 30개 독립 장면·음성 100개 목표. 룬/참/유니크 종류별 자료 분리 | 먼 일반 적 추격 0, 위험 선점·공격 종료 키 해제·처치 확인. 미승인 오클릭 0·열쇠 놓침 0 목표와 표본 한계 공개. 사례 없는 종류의 회수는 미검증 |

| E6 완전 런 | Act 1 재정비 마감 후 새 방의 버프까지 이어지는가? E5B를 포함한 필요한 앞 기능이 모두 검증된 상태 | 전체 녹화 1방→3방→10방→30방. 각 묶음 후 사람 검토; 같은 조건의 연속 묶음으로 판단 | 사망/안전 위반/오폐기 0, 모든 방 결과·보급/용병 상태·종료 확인. 30방 중 27방 이상 정상 마감 목표 제안; 안전 포기도 별도 분모. 회수 운은 이 기능 기준과 분리 |
| E7 파밍 관찰 | 드롭 변동과 시간당 회수 성능을 설명할 수 있는가? E6 통과 및 확대 승인 필요 | 100회 확정 처치의 초기 관찰; 필요 시 같은 조건 약 350회 규모 통계. 10~30방 단위로 계속 검토 | 드롭 빈도·열쇠 수·회수율·시간·포기 원인을 각각 보고. 장시간 무인 승인이나 정밀 드롭률 검증으로 간주하지 않음 |

표본 수는 부족 자료를 드러내는 수집 목표다. 연속 프레임 100장을 독립 장면 100개로 세지 않는다. 온라인에서도 레이아웃이 같으면 같은 그룹으로 기록한다. 재생에서 기능이 통과해도 실제 입력 성공을 대신하지 않는다.

## 매 묶음에서 확인할 항목

- 실험 전: 캐릭터/모드/난이도, 창 영역과 포커스, 체력/마나/벨트/감정·TP 잔량/용병/공간·보호 슬롯, 버프 키, 승인 전리품 룰 버전, 중단 키, 감독자, 횟수·시간 상한.
- 실행 중: 현재 화면과 판단의 일치, 프레임이 바뀐 이후 이전 목표 클릭 여부, 안전 선점, F2/F4 및 마우스 홀드의 해제, 진행 없음과 복구 횟수.
- 실행 후: 전환 전후 프레임을 원본 영상과 대조한다. 탐색 끝/처치/드롭/획득/Act 1 복귀/종료를 각각 확인한다.
- 성공뿐 아니라 안전 포기·시간 초과·사람 개입·인식 불확실도 모두 센다. 사람 개입을 자율 완료로 바꾸지 않는다.
- 실패 묶음은 원인 가설 하나를 고르고 같은 검증 조건에서 비교한다. 속도 향상만 있고 안전/경로 정확도가 낮아지면 개선으로 세지 않는다.
- 다음 단계의 사람 검토는 자료 범위, 미검증 구조, 현재 버전, 변경한 가설을 보고 진행/반복/범위 축소 중 결정한다. 실제 기록은 승인된 런과 평가 문서가 소유한다.

## 중단과 시간 예산

| 사건 | 계획상 요구 |
| --- | --- |
| 사망 또는 치명적 위험 무시 | 즉시 실험 종료, 다음 방 자동 재시작 금지, 실패 증거 보존 |
| 캡처 노후·검은 화면·포커스 상실 | 일반 입력 중단·홀드 해제. 화면/포커스 확인 없이 긴급 키도 보내지 않음 |
| 위험/급감·물약 고갈·마나 부족·용병 사망 | 검증된 회복/탈출 우선. 불확실하면 즉시 감독자 인계; 재정비 전 재개 금지. 일시정지를 안전 복귀로 간주하지 않음 |
| 참 옵션/수치/대상 슬롯 불확실 | 폐기 입력 금지, 격리/보관 대기 또는 인계. 보호 아이템 변화 시 즉시 실험 중단 |
| 버프 확인 실패·장비 복귀 실패 | 출발 금지, 제한 재시도 후 인계 |
| 경로 진행 없음·전투 정체·줍기 재시도 | 승인된 횟수/시간 내 복구만 허용; 초과 시 안전 종료 |
| 사람 조작·중단 요청 | 예약 입력 취소, 이동/공격 키 해제, 자동 재개 금지 |
| 저장 공간/녹화/로그 실패 | 증거를 필요로 하는 다음 묶음 중지; 자료 누락을 성공 평가에 숨기지 않음 |

승인 전에 정할 값: 캡처/인식 결과 유효 시간, 위험 감지→키 해제/회복/탈출의 최대 지연, 상태별 대기/재시도 상한, 날개별 진행 없음 한계, 방/묶음의 총 시간. 먼저 p50/p95/p99와 최악 관찰값을 재생·안전 상황에서 측정한다. 기존 북쪽 경로의 프레임 나이 수치는 생존 검증값으로 재사용하지 않는다.

## 텔레포트·막힘 원인별 관찰 계획

같은 위치에서 움직이지 않는 현상에 같은 복구를 반복하지 않는다. E4/E5A의 실패 클립은 다음 가설별로 분리하고, 입력 없는 재생으로 원인을 분류한 후 안전 조건이 갖춰진 짧은 감독 비교만 제안한다.

| 가설 | 함께 확보할 증거 | 비교할 결과 |
| --- | --- | --- |
| 이동 후 옛 좌표 사용 | 텔레포트 전후 발판/랜드마크, 목표 검출 프레임과 다음 입력 시각 | 다음 입력이 새 화면에서 재획득한 목표를 쓰는가 |
| 마나 부족/이동 스킬 미선택 | 마나·스킬 표시·무기 스왑·F2 누름/해제·실제 이동 | 경로 실패와 자원/시전 실패를 구분하는가 |
| 홀드로 예상보다 많은 텔레포트 | 한 입력 구간의 길이, 시전 횟수, 랜드마크 이동량, 캡처 간격 | 입력 범위를 줄였을 때 이동 결과를 확인할 틈이 생기는가 |
| 공백/잘못된 발판 조준 | 캐릭터 발·통로 경계·목표 위치·층/계단 가림 | 새 관찰에서도 동일 후보를 반복하는가, 안전한 새 진행 증거를 얻는가 |
| 로딩/지연/캡처 노후 | 프레임 시각·프레임 나이·인식 완료 시각·포커스·검은 화면 | 입력 누적 없이 대기/차단되는가 |
| 적 압박/경직 또는 노바 효과 | 근접 적·체력/마나·F4 홀드·효과 전후 지형 | 생존/전투가 이동 복구를 선점하며 효과 변화를 경로 진행으로 오인하지 않는가 |
| 맵 텔레포터/중앙 복귀 오인 | 상호작용 전후 지형, 날개 방문 상태, 중앙 랜드마크 | 이동 스킬과 맵 상호작용을 구분하고 복귀 전 다음 날개를 시작하지 않는가 |

날개별로 클릭 이동과 텔레포트의 입력 구간·랜드마크 이동량·재관찰 지연을 비교하되, 미검증 먼 점프를 먼저 반복하지 않는다. 프레임 차이값만 낮다고 막힘, 높다고 이동 성공이라고 판정하지 않는다.

## 자료 소유와 폴더

현재 공개 가능한 템플릿은 기존 `assets/` 분류를 유지한다. 새 원본 자료를 템플릿과 섞거나 기존 파일 위에 덮어쓰지 않는다. 아래 트리는 **개발 세션 중 검토용 저장 위치 제안**이다. 필요한 인식 자산은 세션 종료 정리 전에 `assets/`에 선별하고 소비자 참조를 확인한다. 원본 트리 전체를 영구 보관하는 제안은 아니다.

```text
recordings/summoner/evidence/<session-id>/
  session.md             환경·승인 경계·자료 목록·보존 여부
  videos/                원본 영상; 생성~종료 또는 승인된 구간
  frames/raw/            원본 프레임
  frames/annotated/      박스·방향·판정이 표시된 복사본
  labels/                사람 정답과 정답 수정 이력
  events/                상태·판단·입력·위험·프레임 시각
  outcomes/              방별 결과·처치/드롭/회수 분리 집계
  cases/                 실패/경계 사례 목록; 원본 위치를 참조
  datasets/              조정/검증/보류 그룹 목록; 원본 중복 복사 지양
```

- `session-id`는 서울 날짜/시각과 충돌 방지 식별자로 구분한다. 예시는 이름 규칙일 뿐 실제 세션이 아니다. 프레임은 방·단계·프레임 번호가 다른 고유 이름을 사용한다.
- `recordings/`와 `assets/private/`는 현재 Git 제외다. 로컬 원본은 업로드/커밋하지 않는다. 파생 템플릿도 검토된 것만 기존 `assets/`의 해당 분류로 반영한다.
- 현재 기본 파일 로그의 `logs/`는 Git 제외가 아니다. 이후 수집에서는 로그를 위 로컬 자료 소유로 복사/연결할지, 로그 설정/제외 규칙을 정할지 승인된 기능에서 결정한다. 이번에는 로그를 생성하거나 설정을 변경하지 않았다.
- 자동 북쪽 녹화의 보존 정책은 성공 영상을 삭제할 수 있고 방/버프 구간이 빠진다. 개발 세션 중 검토가 필요한 원본은 자동 삭제 루틴에서 보호되는지 확인한다. 이는 검토 중 보호이며 세션 종료 정리를 면제하지 않는다. 현재 보호 기능이 완성됐다고 간주하지 않는다.
- GUI 스냅샷은 같은 파일을 덮어쓴다. 원본을 고유 세션 이름으로 보존하는 경계가 확보될 때까지 반복 캡처의 증거 저장소로 사용하지 않는다.
- 개발 중 원본/실패/사람 검토용 자료는 현재 세션의 진단·검증에 필요한 동안 유지한다. 2026-10-05 사용자 지시에 따라 세션 종료 시 필요한 인식 자산만 의미 있는 이름으로 `assets/`에 선별하고 나머지 로그·녹화·중간 프레임·임시 자료를 정리한다. 상세 기준은 [개발 가이드](../project/developer-guide.md#evidence-handling)가 소유한다. 기준 영상/정답 데이터셋의 영구 보존을 기본값으로 두지 않는다.
- 임시 추출/인코딩 캐시는 세션 내 별도 `scratch/`에서만 사용한다. 정리 전 활성 소비자를 중단하고 자산·manifest 참조를 갱신한 뒤, 소유/사용 여부와 정확한 경로를 확인하여 제거한다.
- 실제 런/평가 문서에는 세션 ID·당시 출처·결과 요약을 남긴다. 원본을 정리한 뒤에는 파일이 현재 존재하는 것처럼 안내하지 않으며, 요약된 과거 관측과 현재 재현 가능한 자산을 구분한다.

## 자료 분리와 지표

- 같은 방/같은 레이아웃/같은 영상의 인접 프레임은 한 그룹이다. 그룹 단위로 조정/검증/보류를 분리한다. 충분한 그룹이면 60/20/20을 후보로 검토하고, 부족하면 작은 수와 미검증 범위를 공개한다.
- 구 그래픽과 리마스터, 다른 언어·해상도·계열, 인원/TZ 조건은 분리한다. 현재와 다른 에셋은 이식 가능성의 증거가 아니다.
- 새로운 템플릿/임계값은 조정군에서 정하고 고정한 뒤 검증군을 본다. 실패를 보고 검증군에 맞추면 새 보류 자료로 다시 확인한다.
- 인식: 상태별 오인/미검출/미확인, 라벨별 precision/recall과 원본 장면 수. 근접 판정은 가까움/경계/멀리/가림으로 정답을 나눈다. 미확인을 분모에서 숨기지 않는다.
- 공통 전리품/재정비: 종류별 옵션/수치 오인, 보관 대상 오폐기·판정 불가 폐기·재회수, 실제 보관/구매/문서 충전/부활 성공과 재개 차단 실패를 보고한다.
- 이동: 날개별 자율 완료/안전 포기/실패, 막힘 횟수·복구 성공·복구 시간, 무효 좌표 입력, 중단 후 재합류.
- 안전: 사망·치명 위험 무시·버프 미확인 출발·물약 고갈 후 진행은 모두 0이 목표다. 안전 입력 지연과 위험 자료의 검증 범위를 함께 공개한다.
- 런: 시작 방 전체를 분모로 정상 완료율/포기율/개입률을 계산하고 전체 시간과 구간별 p50/p95를 보고한다.
- 열쇠: 확정 처치 수, 충분히 사후 관찰한 처치 수, 드롭이 보인 방 수, 실제 드롭 개수, 회수 개수, 미확인 수를 별도 보고한다. 드롭 빈도의 분모에는 관찰 충분한 확정 처치만 사용하고 제외/미확인 수를 함께 표시한다.
- 효율: 실제 회수 열쇠/전체 경과 시간. 방 생성·버프·길찾기·줍기·Act 1 마감·오류 처리 시간을 포함한다. 여러 열쇠 드롭 가능성 때문에 1회 이상 드롭 확률과 평균 열쇠 수를 혼동하지 않는다.
- 드롭 통계 해석과 표본 예산은 [열쇠 조사](../research/summoner-key-drop-reference.md)에 둔다. 운이 나쁜 사례를 삭제하거나 조건이 다른 방을 섞어 개선을 주장하지 않는다.

## 사람 확인이 남은 사항

기본 Resurrection·초기 회수 종류·참 보관 조건은 사용자 확인을 반영했다. 실제 버전·그래픽·라벨 설정, Flash 버프별 이름/효과/시전 방식, 벨트/문서/용병·생존 수치, 근접 거리/전투·줍기 예산, 정상 복귀와 Act 1 재정비 수치가 남아 있다. 관련 기능 승인 전에 해결한다. 첫 검토 대상은 E0의 관찰 기준선과 E1의 마을 범위 방 생성·종료이며, 이를 전체 파밍 실행 승인으로 확장하지 않는다.
