# Summoner Run

실행·중단은 [GUI 실행](#gui-실행), 최신 중단 상태와 재개 조건은 [통합 run 세션 마감](../plans/run/run-20261009-07-summoner-live-integration.md#session-close-20261022)에서 바로 확인한다. 아래 판독·입력 계약의 실제 실행 수치는 통합 run이 소유한다.

현재 용병 초상화가 미확인이면 이동/공격을 해제하고 기존 현재 메뉴·실제 커서·새 화면을 검증하는 안전 종료로 넘긴다. 감독 검토를 기다리며 필드에 남기지 않으며 사람 중단/포커스 상실 뒤 종료 입력 금지는 유지한다. 얼굴 기준은 기존 단일 template .92/현재 라벨 가시50%다. 부재를 사망이나 NPC/부활 허가로 해석하지 않는다.입력 없는 검사 통과와 실제 안전 종료 성공은 구분한다. 실게임 재개에는 사람의 시체·장비·용병 복구 확인이 먼저 필요하며 최신 결과는 위 통합 run이 소유한다.

돌바닥 배경의 성역 제목은 검토 변형의 전체와 세 글자 구간 각각 .86으로 확인한다. 갱신 준비에서 현재 제목 확인이 실패하면 추가 버프/정지 감시를 반복하지 않고 기존 현재 메뉴·새 화면·실제 커서를 검증하는 안전 종료로 넘긴다. 재생/회귀 통과와 실제 새 방 마감은 구분하며 최신 결과는 통합 run이 소유한다.

사용자의 생존 최우선 지시에 따라 현재 위험 비율→현재 발/근접 방어→지형·목표·전리품 순서로 처리한다. 한 숫자가 가려져도 다른 현재 비율이50%/10% 미만이면 비상 회복 또는 종료를 먼저 요청한다. 전리품 검사/ALT OFF 복원도 공통 회복을 검사당 최대1회 사용하고 실패/재발은 안전 종료로 넘긴다. 현재 근접 위협이6초 동안 해결되지 않으면 공격만 멈춰 대기하지 않고 안전 종료한다. 최신 화면·실제 커서·포커스/중단·버프 조건과 포션 선택/복귀 검증은 유지한다.

근접 호버 준비 뒤 다음 촬영은 실제 커서 정착50ms까지 남은 시간만 기다린다. 원래 구간/버프 시한·중단과 다음 새 화면의 현재 몸체/패널·실제 커서·250ms는 유지한다. 33번에서16ms 만에 촬영해 호버를 승인하지 못한 사례를 보완했다. 이후38/39번의 현재 근접 양성 화면에서는 촬영→방어 처리46–78ms가 기록됐지만, 적 최초 등장→실제 시전의 지연이나 원인별 개선 비교는 미검증이다.

서모너 전용 전투의 이번 실행에서 새 발판을 실제 확인한 뒤, 현재 발/250ms를 유지하는 재획득 중 발판이 가려지고 녹색 효과 후보가 없으면 현재 발 기준의 제한 근접 격자로 호버한다. 발판을 한 번도 확인하지 못했거나 발/현재 화면을 잃으면 기존1초 중단을 유지한다. 공격에는 계속 새 적 패널·현재 근접 위치/실제 커서·화면 유효시간을 요구하며 과거 발판으로 이동/사망을 만들지 않는다. 노바6초·전체12초 상한과 현재 발판의 두 시체 조건은 유지한다. 구체적인 거부/시한 조건은 [SPEC-0013](../plans/spec/spec-0013-summoner-platform-encounter-evidence.md)이 소유한다.

비상 회복의 벨트 대기는 현재 생명력50%/마나10% 미만을 잔량 승인보다 먼저 처리하고,250ms 이내의 현재 펼침 관측으로 닫아 중복 촬영을 줄인다. 실제 빈 아래 칸 외형은 기존 종류 점수/차이 기준으로 구분한다. 비상 종료는 field backend의 ESC 한 번→현재 메뉴/50ms 정착/새 화면/실제 커서→클릭 한 번→선택 화면 확인이며 마지막 화면과 입력 요청 시각을 남긴다. 상세 시한/거부 조건은 [SPEC-0014](../plans/spec/spec-0014-live-emergency-recovery.md)가 소유한다. 33번의 실제 사망 뒤 실게임을 중단하고 사용자의 수동 복구 확인 후 재개했다. 이후 실게임 발동·실패·안전성의 검증 범위는 통합 run이 소유하며 제한된 무사망 관찰을 전체 안전 수용으로 확대하지 않는다.

전리품 검사와 OFF 복원의 HUD 숫자 미확인은 입력 없이 최대 .75초 새 화면을 다시 읽는다. 같은 화면250ms·패널/저자원/용병·포커스/중단·원래3초 검사/버프 시한은 유지하며 .75초에 도착한 양성도 거부한다. OFF 안전 복원만 기존 버프 만료 예외를 유지한다. 마지막 HUD 미확인 화면 한 장과 비율/복원 단계·재획득 시각을 덮어쓰는 진단으로 남기고 이전 숫자를 채워 넣지 않는다.

서모너 외형의 축소 검색에서 두 번째 몸체 후보만 빠지는 경우를 막기 위해, 원본 RGB를 통과한 부위에 한해서 같은 원본 범위/임계값으로 떨어진 다른 몸체도 거부한다. 이 검사는 새 대상을 승인하지 않으며 기존 후보 상한과 현재 발판·250ms/두 시체 조건을 유지한다.

아이템 F2 준비는 현재 라벨을 재확인하고 ALT OFF를 보낸 동안 지난 커서 정착 시간을 포함해, 실제 커서 이동 뒤50ms까지 남은 시간만 기다린다. 같은 라벨 화면의 원래250ms·현재 커서·중단/포커스·버프/3초 검사 상한은 그대로다. 새 시체 쌍 확인 뒤 이 추가 대기로 막힌 같은 방 복구를 근거로 보완했으며 전송/클릭을 획득으로 해석하지 않는다.

## GUI 실행

프로젝트 루트에서 `python main.py`를 실행한다. 게임 창·캡처 방식을 선택하고 실제 게임 캐릭터와 같은 `Character`, `Difficulty`, `Repeat Count`를 지정한 뒤 `Summoner Run`을 누른다. 횟수는 1–5이며 빈 값은 1이다. 프로필 선택은 게임의 실제 캐릭터 선택을 바꾸지 않는다.

시작 조건은 캐릭터 선택 화면, 실제 캐릭터 사전 선택, 메인 무기 세트, ALT 표시/숨기기 토글 방식이다. 검토 배치는 리마스터 한국어 1922×1140 기준 프레임이다. 설정한 공통 캡처 계층이 실제 게임 내용 영역을 기준 프레임으로 정규화하고 이동/호버/줍기/메뉴 좌표를 실제 창으로 역변환한다. OS 제목 표시줄·테두리를 따로 다루고 내용 비율 오차1% 밖이면 거부한다. 창을 활성화할 때 분할/최대화 배치를 복원 크기로 바꾸지 않는다. 좌표가 맞아도 축소로 글자/텍스처 정보가 사라질 수 있어 작은 실제 창에서 판독/완주 검증이 필요하다. 다른 언어·게임 UI 배율 설정·그래픽·모든 클래스의 전투 관찰은 미검증이다. 생존 정책·클래스/FCR·키 배정은 선택한 캐릭터 설정을 사용한다.

`Stop Action` 또는 F10으로 중단한다. 필드 F8도 현재 중단이며 재개 기능이 아니다. GUI는 worker 이벤트를 받고 동시에 다른 게임 입력 작업을 시작하지 않는다. 창 닫기는 중단 요청 후 정리를 기다린다. GUI는 live 입력이며 CLI `dry_run`과 별개다.

보고서는 `recordings/summoner/evidence/gui-<시각>-<고유값>/report.json`과 각 방의 `report.json`이다. 미완료 경로나 처치 미확인에서는 생존 감시·허용된 근접 방어를 유지하며 새 방을 생성하지 않는다. 인계/포커스 상실은 입력을 해제한다. 실제 저자원/지속 HUD 미확인은 회복 소비 또는 안전 종료를 시도하고 사람 확인 대상으로 남긴다.

## Current staged implementation

실행 경로는 `main.py`→GUI→`SummonerGuiSession`→`main_run.run`→`run_once`다. 예전 `north_go.py`·`north_return.py`와 `North Go Test` 버튼은 제거했다. CLI도 같은 실행기를 사용한다.

```powershell
.\.venv\Scripts\python.exe main.py --summoner-run --live --continuous-north --field-seconds 60 --north-segments 4 --north-cycles 1
```

`--live` 생략 시 게임 입력을 보내지 않는다. 정상 GUI는 새 방에서 시작한다. 기존 방의 ALT 상태를 화면만으로 확정할 수 없어 상태 근거 없는 자동 재개는 거부한다. 중단한 프로그램의 최종OFF 기록 이후 토글이 없었음을 확인한 감독 복구만 `--resume-labels-off`로 시작 상태를 명시할 수 있다. 이 옵션은 `--resume-arcane` 또는 `--return-to-hub-from`과 함께 사용하며 새 방에는 넘기지 않는다. 과거 감독 JSON 재개 예시는 [이전 참고](summoner-run-legacy.md)에 보존했으며 현재 GUI 절차가 아니다.

## 자동 버프와 생존

Flash 순서는 `w→a→a→s→d→F1→w`이며 d는 에너지 쉴드, F1은 냉기 갑옷이다. 매 방 메인 무기 시작은 사용자 전제다. W 균형으로 시작 세트 복귀를 관리하며 부분 시전 뒤 자동 W 복구를 추측하지 않는다. 인벤토리 I와 캐릭터별 I/II 탭 확인은 없다.

초기 1초의 확인 가능한 생명력·마나 비율 변화 5%p 이내, 닫힌 벨트·패널·포커스·현재 근접 적 후보를 확인하고 각 키 전 재관찰한다. 먼 적만으로 버프를 금지하지 않는다. 후보 미검출은 모든 적 부재 증명이 아니며 보고서도 범위를 명시한다. 생존 판단은 현재 화면의 current/max 비율 또는 검증한 구체 하한을 사용하며 레벨·장비별 고정 수치를 쓰지 않는다.

타이머는 실제 해당 키 요청의 단조 시각부터 계산한다. Flash는 전투 지시 150초−여유 10초, 즉 실제 S 요청+140초다. 현재 GUI는 안정 관찰·마지막 무기 복귀W까지 확보하도록5초 먼저 이동/공격 해제→새 안전 관찰→전체 순서를 준비하며, 새 관찰 뒤 같은 경로 객체를 이어간다. 준비 시점과 실제140초 시한을 구분하고 첫W/S/마지막W를 따로 검증한다. 대기 중에도 갱신하며 `field_safety`/`initial_effect` 감독 JSON을 기다리지 않는다. 완료 전송은 `dispatched_unconfirmed`, 전체 효과는 `not_independently_verified`다. 이전4초 정책의 네 갱신에서 첫W와S는 제때였지만57번 두 갱신의 마지막W는 .390/.344초 늦었다.5초 여유의 실제 결과·다른 적/지연 조건·전체 효과는 별도 검증한다. [버프 계약](field-buffs.md)이 확인 API와 실행 정책의 차이를 소유한다.

## 조건부 ALT

2026-10-11 사용자 결정으로 항상 ON 기본값을 교체했다. 새 방 기본 OFF→이동 OFF→실제 노바 전송 종료 후 ON→드롭 검사·제한 클릭→OFF→새 화면 재관찰 순서다. 전투 OFF에서 타이머만으로 ALT를 토글하지 않는다. 전송 기록과 실제 표시·획득을 구분한다.

현재 설정의 증오의 열쇠·허용 룬·자수정 라벨만 검사한다. 작은 활력은 현재 확인 잔량6개 이하일 때만 허용하는 정책이나 포션 라벨 자산이 없어 실제 포션 줍기는 미지원이다. scan 상한은3초/12프레임/2클릭이다. 필드 아이템을 현재 라벨로 조준한 뒤 ALT OFF→F2 한 번→시전 참고 시간→ALT ON→새 라벨과 현재 발의 근접 확인→새 위치를 조준/재인식→클릭→OFF 순서를 지킨다. 각 입력 전 새 HUD·포커스·패널·같은 후보·커서·250ms/버프 시한을 검사한다. 시전 대기나 전송만으로 착지 성공을 선언하지 않는다. 중단/포커스 상실로 OFF 복구 입력을 보낼 수 없으면 unknown으로 두고 이동을 막는다. 클릭은 `click_unconfirmed`이며 실제 인벤토리 증가 생산자는 아직 없다. 미확인 클릭이 있는 보스 방은 자동 협곡 마감을 승인하지 않는다. 후보가 없는 두 현재 프레임의 제한 검사 완료는 열쇠가 절대 없다는 증거가 아니다.

## 지도와 자산

정상 main은 자동지도 ON을 지역 제목으로 확인한다. 이미 확인한 끝의 정지 재획득에서만 위의 한 번 숨김/복원 절차를 허용한다. 바닥·배경 대응이 조향을 맡는다. 투명도 47은 고정 운영값이 아니며 크기·위치·투명도 변화에 견디는 지도 선 해석/추적은 미구현이다.

지형/상자/룬/적은 `assets/regions/arcane-sanctuary/`, 소서리스 표식은 `assets/character/sorceress/`, HUD·자동지도·마을 UI는 `assets/ui/`, 카메라 배치는 `assets/ui/layouts/`가 소유한다. 타일 variation·계단·텔레포터 유형은 해석 참고이며 고정 경로 정답이 아니다. 개인 정보가 없는 재생용 전체화면도 공용 references로 둔다. 현재 소비자가 없는 개인 원본 이미지는 세션 정리에서 제거했으며 개인 보고서/바인딩 메타데이터는 ignored 로컬 이력이다. [assets 입구](../../assets/README.md)가 분류·명명·보존 기준을 소유한다.

[과거 설계·실행 참고](summoner-run-legacy.md)는 교체 전 상태와 timeline을 보존하며 GUI 실행에 필요하지 않다. 다음 개발은 이 문서와 최신 통합 run을 기준으로 시작한다. `references/encounters/specter.webp`는 대체 검토 자산이 없는 레이쓰 외형 참고이며 실제 파일 형식도 WEBP다. 현재 종류별 인식 소비자는 없고, 서모너는 별도의 검토된 생존/시체 PNG를 사용한다.
