# 생존 화면 관찰

현재 판독 기준은 v21이다. 기존 단일54×54 용병 얼굴 template의 전체 일치를 .92로 확인하고, 전체 미일치 때만 현재 라벨 mask·같은 얼굴 최소50% 가시·동일 .92를 요구한다.61번 얼굴 .923433과 검토 양성6개/음성12개의 제한 비교를 반영했으며 새 runtime template은 없다. 부재/불일치는 미확인이지 체력·사망 판정이 아니다. main의 미확인은 사용자 중단/포커스 조건을 지키는 기존 안전 종료로 전달한다. 수치·원본/보존 해시는 [공용 자산](../../assets/ui/survival/README.md), 실제 실패·사망 후 상태와 복구 대기는 [통합 run 세션 마감](../plans/run/run-20261009-07-summoner-live-integration.md#session-close-20261022)이 소유한다. 아래 버전별 보정은 해당 시점의 근거이며 일반 정확도나 생존 수용을 뜻하지 않는다.

main 소비자는 현재 읽힌 생명력50%/마나10% 미만을 다른 숫자/벨트의 미확인보다 먼저 처리한다. 미확인 값을 보완하거나 관찰기 자체가 입력하는 것은 아니다. 포션은 현재 닫힌 벨트의 보이는 종류로만 선택하며 이후 두 새 비율·실제 잔량·닫힘이 모두 확인돼야 복귀한다. 전리품 검사/복원과 대기 방어도 같은 회복/실패 종료 계약을 사용한다.

v20에서는 실제 첫 열 맨 아래 빈 칸 외형을 추가했다. 기존 empty 거리 .038572와 scroll .059113의 차이 .02054가 margin .025에 못 미쳐 잔량을 거부한 자료다. 전역 기준 완화와 비교한 뒤 실제 base 외형을 추가해 item distance .075/margin .025를 유지했다. 전체16칸은0/4/4/4로 읽고 보라 포션·스크롤 base는 각각의 종류로 유지한다. 벨트 전용 원본과 별도 HUD를 합성한 검사는 같은 전투 화면의 HUD 증거가 아니다. 원본/해시는 공용 자산이 소유한다.

v19에서는 실제 가림 없는 얼굴 .934801과 음성 자료를 비교해 기존 단일 얼굴의 기준을 .95→.93으로 조정한다. .94는 해당 양성을 계속 놓치며 .93은 검토 양성5개와 실제 음성2개·합성 제거/오외형/가림8개를 구분했다(음성 최고 .634700). 별도 외형 추가도 가능했지만 이번에는 더 단순한 기준 조정을 채택하고 crop은 재생 근거로만 보존한다. 현재 얼굴·라벨 mask의 최소50% 가시·미확인 입력 중단과 다른 HUD 기준은 유지한다. 이 제한된 비교를 일반 정확도나 생존/사망 시각으로 확대하지 않는다. v15–18의 .95와 v19의 .93은 당시 보정 이력이며 현재 실행 기준은 위 v21의 .92다.

v18은 새 얼굴 승인 방식을 추가하지 않는다. 이전 왼쪽 위 커서 해소가 만든 파란 효과는 기존 얼굴 .444128로 계속 거부하고, 공통 좌표 계층으로 OS 제목 표시줄 중앙에 커서를 치운 새 화면의 .996925 얼굴만 기존 .95로 관찰한다. 음성/양성 얼굴 전용 원본과 해시는 survival manifest가 소유한다. 이전 위치의 거부를 완화하거나 용병 체력/생존을 추정하지 않는다.

v17은 붉은 포탈 빛이 붙은 현재 숫자5의 검토 외형만 추가했다. 실제 실패 화면의 life1580/1580·mana928/1543을 기존 검은 외곽선 분리와 glyph .72/차이.08·같은 화면의 current/max/범위 조건으로 읽는다. 숫자 텍스트만 남긴 공용 원본과 정규화 glyph/해시는 survival manifest가 소유하며 벨트·개인 스킬 배정은 제외한다. 과거 최대값이나 구체 하한으로 새 숫자를 만들지 않으며 숫자 제거/미확인 외형은 계속 거부한다. 저장 화면 보정과 이후 새 방 실전 통과는 구분한다.

v16은 ALT 아이템 라벨에 가린 현재 용병 얼굴을 보완한다. 전체 얼굴 미일치 때만 공통 현재 라벨 mask를 적용하고 같은 native 얼굴의50% 이상·기존 .95 이상 상관을 요구한다. 검토 원본은 가림을 제외한 .989037/가시50%이며 얼굴 제거·다른 외형·충분한 얼굴 부재·전체 가림은 여전히 미확인이다. 과거 관찰/체력바로 상태를 대체하지 않는다. 2026-10-20 실제 새 방에서 가림에 따른 용병 미확인과 ALT 복원 차단이 발동했고 기존 north return으로 감독 복구했다. 미확인 중단은 구현대로 동작한 것이며 다음 새 방의 정상 마감 여부는 [통합 run 개발 재개](../plans/run/run-20261009-07-summoner-live-integration.md#development-resume-20261020)에서 검증한다.

v15는 공통 정규화 프레임에서 검토된 Act2 용병 얼굴만 선택적으로 관찰한다. 체력바/이름을 제외한 현재 얼굴 .95 이상을 `observed`, 가림/부재/지원하지 않는 크기를 `unverified`로 구분하며 사망이나 체력을 추정하지 않는다. Flash 새 Summoner 런은 미확인 시 입력을 중단하고 감독 검토를 요청한다. 같은 방 복구는 이 요구에서 제외하며 NPC 부활은 구현/실행하지 않는다. 감시를 켠 GUI70/72 새 방의 정상 마감은 확인했으며 보호 중단 분기는 당시 미검증이었다. 이후 실제 가림 중단은 위 v16 기록을 따른다. 최신 회귀/실행 결과는 [통합 run 개발 재개](../plans/run/run-20261009-07-summoner-live-integration.md#development-resume-20261020), 판독 범위와 출처는 [공용 자산](../../assets/ui/survival/README.md)가 소유한다.

v14는 실제 첫 열 위3칸이 비어 있는 현재16칸 벨트에서 두 중간 행 empty 외형을 추가했다. 기존 item distance .075/margin .025·전체16칸/닫힘 확인은 유지하며, 모르는 칸을 비었다고 추정하지 않는다. 비상 회복 중 잔량 재확인 실패는 여전히 진행을 거부하고 마지막 미확인 벨트 화면과 칸별 판독을 남긴다. [통합 run Attempt18](../plans/run/run-20261009-07-summoner-live-integration.md#현재-attempt18-3런마다-속도경로-보완)이 실제 실패/보정 결과를 소유한다.

[관찰 기능](../plans/feature/feat-0005-survival-screen-observation.md)은 생명력·마나 숫자와 펼친 벨트의 종류/잔량을 읽는 입력 없는 진단 도구다. 판독기는 검토한 한국어 리마스터1922×1140 기준 프레임을 받으며, 설정한 창 캡처는 [공통 기하](../plans/refactoring/refactor-0001-frame-coordinates.md)로 내용 영역을 정규화한다. 다른 크기에서의 숫자/벨트 정확도는 따로 검증하며 크기 변환만으로 보장하지 않는다. 이 관찰 도구는 게임 입력을 보내지 않는다. main의 비상 회복 소비는 아래 후속 통합 경계에서 별도로 다룬다. 실제 자료는 [마을 기록](../plans/run/run-20261005-03-survival-screen-observation.md)과 후속 [필드 버프 기록](../plans/run/run-20261005-04-field-buff-confirmation.md)이 소유한다.

기존 구슬 하한을 명시적으로 켠 소비자는 글자 두 개가 모두 미확인일 때에도 현재 닫힌 HUD 테두리의 색상 거리≤.06·모양 상관≥.90와 두 현재 액체 띠가 모두 양성인 경우에만 기존.90/.60 하한을 사용할 수 있다. 실제 현재값/최대값과 숨은 벨트 잔량은 만들지 않는다. 기본 숫자 전용 동작과 읽을 수 있는 낮은 값/잘못된 최대값의 거부는 그대로이며, 테두리·독/가림·충분한 액체 조건 중 하나라도 미확인이면 진행을 승인하지 않는다. [공용 자산](../../assets/ui/survival/README.md)이 축소 HUD 재생과 음성 자료의 경계를 소유한다.

## 사용

프로젝트 루트에서 안전한 마을의 게임 창을 최소화하지 않고 실행한다. 잔량을 읽으려면 벨트를 펼치고, 확인 후 backtick으로 닫는다. 명령은 창을 활성화하거나 벨트를 토글하지 않는다.

```powershell
.\d2bot.exe survival-observe --live --frames 3
```

`--image <path>`로 전체 native 창 PNG를 읽을 수도 있다. live/image 중 하나만 선택하고 `--frames`는 1–5개로 제한한다. `--output <path>`는 JSON만 저장하며 원본 화면을 저장하지 않는다. 다른 배치를 강제로 resize해서 현재 레이아웃으로 취급하지 않는다.

선택적 정책 진단에는 `--character flash --room <room-id> --age-limit <seconds>`를 함께 제공한다. `--character`는 정책 선택이며 게임 안의 캐릭터 이름을 확인하는 기능이 아니다. age limit은 사용자가 명시한 진단 값이며 검증된 실게임 생존 지연 상한이 아니다. 각 프레임을 독립적으로 판단하며 버프 시각·이전 잔량을 가정하지 않는다.

## 결과와 개인 설정

- 생명력·마나: `current`, `maximum`, `ratio`, 판독 이유. 같은 프레임의 현재값/최대값으로 비율을 계산한다. 전투 지시나 장비 변경으로 최대값이 달라져도 이전 최대값을 재사용하지 않는다. 값 하나라도 불명확하면 해당 비율은 미확인이다.
- 벨트: `belt_visibility`의 `expanded`/`closed`/`unknown`과 4×4 슬롯의 종류. 닫힘은 별도의 테두리 증거로 확인한다. 전체 슬롯과 [개인 정책](../../config/characters/characters.md#survival)의 열별 종류/capacity가 맞아야 잔량을 전달한다. 닫힌 벨트의 한 줄로 총량을 추정하지 않는다.
- 추적 정보: layout/revision, 프레임 순번, 캡처 시작/획득/판독 종료의 `perf_counter` 시각과 각 구간 소요 시간. 이는 도구 호출 경계이며 게임 렌더러의 원본 프레임 시각을 증명하지 않는다. 별도 프로세스의 값을 버프 타이머로 합치지 않는다.
- 정책 결과: 포션·보충·종료·보류 **요청**만 반환한다. 위치는 `unknown`, 주변 적 없음은 미확인, 버프 효과/시전 시각도 미확인이다. 일반 상태에서 `buff_requires_field` 보류는 출발 허가가 아니다.

Flash의 임계값은 현재 최대 생명력의 50% 미만 또는 최대 마나의 10% 미만이다. 최대 생명력이 985에서 1970으로 바뀌면 985는 정확히 50%이므로 요청하지 않고 984부터 요청한다. 둘이 동시에 낮아져도 포션 요청은 하나다. 임계값·키·벨트 배치·버프 지속시간은 캐릭터 설정, 화면 모양/숫자는 [공통 자산](../../assets/ui/survival/README.md)의 책임이다.

## 자료 범위와 후속 작업

한 Act 1 마을의 전체/한 칸 빈 벨트·닫힘·복구와 후속 아케인 중앙 버프 시전의 최대값 변화를 대조했다. 네 자리 최대값에 따른 라벨 이동과 관찰한 마나 라벨 변형을 처리한다. 정확한 표본 값·crop geometry는 [공통 자산의 출처](../../assets/ui/survival/README.md#provenance), 실제 준비와 대조 결과는 위의 마을/필드 기록이 소유한다.

같은 장면의 자료이므로 독립적인 여러 방/배치의 정확도 증거로 계산하지 않는다. 50%/10%·6/0개 판단, 시전 중 적 접근·지연·모호한 효과의 경계 검사는 합성 검증이다. 실제 저체력에서 포션 요청/회복 관찰은 아래 재개33번에 기록하지만 독·격전 전반, 모든 빈 슬롯 위치, 다른 창/언어와 자동 주변 안전·버프 종류 판독은 미검증이다. v5는 실제 main 버프의 HUD 4/6 변형을 추가했고 숫자 2의 패널 추출 마스크는 실제 HUD 검증이 남아 있다. 기존 이동 자료의 1530/1543 미판독은 독립 HUD 4 변형으로 해소되어 양성 재생 자료로 정정했다. 진짜 모호한 마을 구분자 자료는 계속 거부하며 판독 점수/차이 기준은 유지한다.

현재 `purple_potion`은 관찰한 큰 보라색 완전 활력 포션 외형만 지원한다. 일반 활력 포션이나 다른 그래픽은 자료를 별도로 확보해야 한다. [Arreat Summit의 포션 자료](https://classic.battle.net/diablo2exp/items/potions.shtml)는 일반/완전 활력 포션의 회복량과 벨트 기본 동작을 설명하는 참고다. 현재 HUD의 정답은 직접 캡처에서 확인하며, [Reign of the Warlock의 공식 안내](https://news.blizzard.com/en-us/article/24243863/rain-annihilation-in-reign-of-the-warlock)는 별도 확장/변경 확인에 사용한다. 과거 자료를 현재 모든 게임 계열의 검증으로 확대하지 않는다.

후속 [버프 확인/벨트 종료 계약](field-buffs.md)은 감독 시각 증거와 입력 요청을 분리한다. [비상 회복 통합](../plans/feature/feat-0015-live-emergency-recovery.md)은 현재 닫힌 벨트의 보라 포션 열1회 입력→새 HUD 회복→실제 펼친 벨트 잔량→닫힘을 main 이동/전투/대기에 연결했다. 닫힌 한 줄은 입력 열 선택에만 사용하며 총량은 펼친4×4 판독으로 확인한다. 재개33번의 첫 요청은 새 회복·실제 잔량·닫힘까지 확인했으나 두 번째는 회복 뒤 잔량/닫힘 미확인, 안전 종료도 미확인으로 끝났고 직후 감독 화면에서 실제 사망을 확인했다. 키 요청만으로 소모/획득이나 잔량을 확정하지 않는다. 벨트 대기의 현재 저자원 선점과 종료 경로를 보완했으며 수정 후 실게임 안전성은 미검증이다. 자동 안전 필드/버프 효과 생산·획득 확인·재보급·사망 복구는 남아 있다. [Arcane 이동 PRD](../plans/prd/prd-0005-arcane-navigation-and-recovery.md)는 이를 바탕으로 웨이포인트 진입, 텔레포트 도착/다음 입력 가능 관찰, 직업별 FCR과 관측 지연에 맞춘 이동을 다룬다.
