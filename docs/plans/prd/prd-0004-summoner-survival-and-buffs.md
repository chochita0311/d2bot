## Request Summary

캐릭터 사망을 허용하지 않는 서모너 런의 안전 경계와 매 방 버프·런 도중 갱신 조건을 정의한다. 공통 판단은 캐릭터별 설정을 사용하며, 이동·전투·줍기 전과 진행 중에 버프 유효성·회복 자원·탈출 준비를 확인한다.

후속 [FEAT-0008](../feature/feat-0008-field-control-loop.md)은 독립 입력 해제/생존 선점, 포션 확인과 새 벨트 절대 잔량 연결, 프로필 순서·간격의 연속 버프 실행기를 추가한다. [실행 기록](../run/run-20261005-06-field-control-loop.md)이 단위/주입형 검증과 짧은 실제 입력을 구분한다. 자동 안전/효과 확인·포션 획득·실제 고갈 종료 소비자는 남아 있다. 이전 FEAT의 제한은 그 당시 승인/검증 경계다.

## Product Intent

사용자는 현재 체력·마나·물약·버프의 관찰 신뢰도와 진행 허용 여부를 알 수 있어야 한다. 생존이 불확실하면 파밍 진행을 포기하고 검증된 탈출 또는 사람의 즉시 인계를 우선한다.

## Confirmed Scope

- 생명력, 마나, 벨트의 물약 종류·잔량, 필요한 탈출 수단, 빌드가 의존하는 용병 상태를 화면에서 관찰한다. 버프/장비로 최대 생명력·마나가 바뀌면 같은 최신 프레임의 현재값/최대값으로 임계 비율을 계산한다. 가려지거나 읽을 수 없는 값은 정상값이나 이전 최대값으로 대체하지 않는다.
- 회복 물약·활력 물약·마나 보충·후퇴·비상 종료의 우선순위와 허용 조건을 캐릭터별로 정한다. 급격한 체력 감소와 회복 실패도 판단 대상이다.
- 안전 판단은 이동·전투·줍기·버프 대기·복구 중에도 유효해야 한다. 행동 중 체력 관찰이 끊기거나 입력을 중단할 수 없으면 장시간 동작을 허용하지 않는다.
- 일반 행동의 동시 입력 충돌을 방지한다. 비상 행동은 진행 중인 이동/공격/줍기 입력을 선점하고 눌린 입력을 해제할 수 있어야 한다.
- 매 새 방에서 버프 확인을 새로 시작한다. 이전 방의 완료 상태나 단축키 전송 성공을 새 방의 버프 완료 증거로 재사용하지 않는다.
- 버프 순서, 무기 전환, 실제 시전 가능한 안전 위치, 마나, 시전 완료, 전투용 장비·이동 스킬 복귀를 확인한다. 버프는 각 Act의 마을/마을 웨이포인트에서 시전하지 않고 마을 밖 필드에서만 진행한다.
- Flash의 버프 입력과 설정은 최근 사용자 지시 `w → a → a → s → F1 → d → w`를 따른다. 과거 입력 순서를 대안으로 남기지 않는다.
- 눈에 보이는 효과·HUD 변화 등 버프별 증거를 정한다. 효과를 확실히 읽을 수 없으면 감독자의 명시적 확인 또는 진행 보류를 요구한다.
- 런 도중에도 필수 버프 중 가장 짧은 지속시간을 기준으로 갱신한다. 버프별 시전 시점이 다르면 가장 먼저 만료되는 버프를 기준으로 한다. 실제 시전 근거의 시각으로 유효 시간을 추적하고, 키 전송·재시도 요청만으로 만료 시각을 연장하지 않는다. 같은 방에서 프로그램을 일시정지해도 경과 시간은 계속 반영한다.
- 최초/재버프 모두 최신 화면에서 주변 몬스터가 없고 HUD·위치를 관찰할 수 있는 안전한 상황에서만 진행한다. 단순 몬스터 미검출은 안전 확정이 아니다. 시전 중 적 접근·위험·미관찰이면 일반 버프 입력을 취소하고 생존 처리를 우선한다. 필수 버프가 만료되면 일반 필드 진행을 허용하지 않으며, 안전 확보 실패를 위험한 재버프 강행으로 해결하지 않는다.
- 벨트는 안전한 초기 화면 관찰을 기준으로 종류·열별 잔량을 파악하고, 확인된 소모·획득 결과로 갱신한다. 주기적 관찰과 수동 사용·재배치·불일치 뒤 재관찰로 상태를 대조한다. 키 누름은 실제 소비, 라벨 클릭은 실제 획득으로 집계하지 않고 중복 결과도 재집계하지 않는다.
- 잔량 확인을 위해 펼친 벨트는 관찰 뒤 backtick으로 닫고 최신 닫힘 증거가 있어야 일반 이동을 허용한다. 키 전송/펼침 미검출만으로 닫힘을 확정하지 않는다.
- 포션/스크롤 사용 뒤 결손을 기록하고 이동 중 보충을 요청한다. 가득 유지하는 목표와 소모 직후의 결손을 구분한다. 자원 상태·회복/중단 판단은 본 PRD, 접근/획득 확인·보충은 [PRD-0007](prd-0007-shared-loot-and-town-maintenance.md), 보충을 위한 전투는 [PRD-0006](prd-0006-summoner-combat-and-loot.md)이 소유한다.
- 버프 순서·지속시간·갱신 여유·안전 판정, 벨트 열/종류·확인/사용 키·목표량, 체력/마나 임계값·재사용 간격·고갈 처리·보충 전투 진입/해제 조건은 캐릭터별 설정이다. 공통 엔진을 캐릭터 이름으로 분기하지 않는다. 다른 캐릭터의 미설정 값을 Flash 값으로 대신하지 않는다.
- 위험/사망 화면/연결 단절 발견 후 다음 방 자동 재시작을 금지하고 원인과 마지막 증거를 남긴다.
- F2 텔레포트와 F4 노바 홀드 중에도 생존을 관찰하고 위험 시 해당 키를 해제한다. 사용자 표현의 에너지 소진은 체력/마나 관찰·회복으로 구체화하며 에너지 능력치 자체를 소모 자원으로 해석하지 않는다.
- 용병 사망 확인 시 필드 진행을 보류하고 안전 복귀를 우선한다. 물약/문서 재보급과 부활 완료는 [공통 재정비 PRD](prd-0007-shared-loot-and-town-maintenance.md)가 소유한다.

## Character Policy

다음은 사용자가 확인한 Flash의 초기 값이며 다른 캐릭터의 기본값이 아니다.

| 항목 | 확인된 값과 결과 |
| --- | --- |
| 최초 버프 순서 | `w → a → a → s → F1 → d → w`; 반복 `a`를 유지하고 전투 상태 복귀를 확인 |
| 최단 버프 | `s`의 Battle Orders(전투 지시), 150초 |
| 갱신 여유 | 만료 10초 전부터 안전한 갱신 준비; 해당 버프 시전 기준 140초에 갱신 필요, 150초에 만료 |
| 벨트 배치/목표 | 1·2·3열 보라색 포션 총 12개(열당 4개)를 가득 유지, 4열은 타운포탈 스크롤 |
| 벨트 확인 | backtick(U+0060, 일반 키보드의 1 왼쪽 키); 펼친 실제 슬롯을 관찰한 뒤 같은 키로 닫고 확인 후 이동 |
| 포션 사용 | 현재 최대 생명력 대비 50% 미만 **또는** 현재 최대 마나 대비 10% 미만이면 보라색 포션 사용; 버프 전 최대값을 재사용하지 않으며 두 조건이 동시에 충족돼도 같은 판단으로 이중 소비하지 않음 |
| 포션 고갈 | 확인된 보라색 포션 잔량 0이면 모든 일반 행동을 선점하고 Esc→게임 종료로 강제 런 종료; 부족 포션을 찾는 사냥보다 우선 |
| 이동 중 보충 | 실제 사용 후 결손을 기록하고 사냥에서 나오는 필요한 포션/스크롤을 회수 |
| 보충 전투 진입 | 보라색 포션이 12개 중 6개 이하이면 이동 중 보이는 몬스터를 사냥하며 보충; 실제 전투 범위와 종료 조건은 PRD-0006과 연결 |

포션 사용·종료는 명령 전송과 결과를 구분한다. 종료 메뉴/선택 화면을 확인하기 전에는 런이 끝났다고 선언하지 않으며, 확인된 고갈 종료 뒤 다음 방을 자동 시작하지 않는다. 잔량을 읽지 못한 상태는 0/가득 참과 별개로 다룬다. 포션 종류·TP 잔량은 화면에서 확인한다.

## Excluded Scope

- 실제 캐릭터를 저체력·사망 상태로 유도하는 테스트.
- 미확인 빌드에 임의 생존 수치 또는 물약 단축키를 적용하는 것.
- 자동 시체 회수, 하드코어 캐릭터를 대상으로 한 미검증 실험, 장비 구매·교체.
- 승인된 상태 계약/관찰 기능을 넘어 미검증 자동 회복·종료·버프 제어를 실행하는 것.

## Constraints

- 무사망은 필수 수락 조건이다. 사망 1회 또는 치명적 위험 대응 실패 1회면 해당 실험을 실패 처리하고 확대를 중단한다.
- 화면 기반 제어로 무사망을 절대 보장한다고 주장하지 않는다. 제한된 표본의 무사망은 다음 감독 검토를 위한 증거다.
- 일시정지·프로그램 중단은 게임 세계의 정지가 아니다. 위험 상태에서는 검증된 비상 동작/사람 인계가 필요하며 입력 중단만으로 안전 복귀를 선언하지 않는다.
- 비상 종료는 화면과 모드에서 검증된 경우에만 선택한다. 포커스를 잃은 상태에서 다른 앱으로 긴급 키를 보내지 않는다.
- 방 관찰/입력 중단 경계는 [PRD-0003](prd-0003-summoner-room-lifecycle.md)에 의존한다. 생존 검증 전 텔레포트·전투·줍기의 필드 반복을 승인하지 않는다.
- 최신 화면·늦은 결과 무효화·비상 입력과 기록 분리의 공통 조건은 [PRD-0008](prd-0008-realtime-runtime-and-recording-retention.md)이 소유한다. 버프·벨트 상태는 방/캐릭터/관찰 시점이 맞는 증거만 사용한다.
- 공통 판단·인식 자산과 개인 설정을 분리한다. 공통 UI·몬스터·포션/스크롤 외형은 배포용 `assets/` 후보이며 개인 이름 이미지와 로컬 보정은 개인 소유다. 이번 경계에서 기존 자산 이동·이름 변경을 수행하지 않는다.

## Candidate Features

- Foundation 후보: HUD 신뢰도·시간 한계·비상 선점의 안전 계약.
- Product 후보: 생명력·마나·벨트 상태의 관찰 전용 표시.
- Product 후보: 검증된 회복 및 안전 탈출.
- Foundation 후보: 캐릭터별 버프 증거와 재확인 조건.
- Product 후보: 새 방마다 버프 확인과 출발 차단.
- Foundation 후보: 캐릭터별 최단 버프 유효시간·안전 시전·갱신 요청의 상태 계약.
- Product 후보: 주변 적 없는 상황에서 런 도중 재버프와 전투 상태 복귀 확인.
- Foundation 후보: 캐릭터별 벨트 배치·자원 상태·소모/획득 결과·재관찰 계약.
- Product 후보: 벨트 관찰·결손 표시와 회복/고갈 종료/보충 요청.

첫 승인 기능은 [캐릭터별 생존·버프 상태 계약](../feature/feat-0003-character-survival-state.md)이며 후속 [HUD·벨트 관찰](../feature/feat-0005-survival-screen-observation.md)과 [감독 필드 버프/벨트 닫힘](../feature/feat-0006-field-buff-confirmation.md)도 제한한 경계에서 통과했다. 다른 후보는 후속 기능 검토 대상이다. 화면 준비/감독 시전과 자동 생존 입력을 구분하며 생존 보증을 상태 이름에 암묵적으로 넣지 않는다.

첫 FEAT-0003 승인 경계는 **캐릭터별 생존·버프 설정과 관찰 상태 계약**이었다. 캐릭터 설정이 정책을 소유하고 확인된 관찰/결과가 현재 상태를 소유하며, 공통 판단은 재버프·회복·고갈 종료·보충 필요를 입력 없는 결과로 반환한다. Flash의 140/150초, 체력 50%·마나 10% 경계, 포션 7/6/0개·미관찰과 다른 캐릭터 설정을 구분한다. 후속 FEAT-0005는 안전한 마을 준비·실제 캡처/공통 자료·입력 없는 HUD/벨트 판독을 추가했다. 필드 전투·자동 생존 입력·기존 자산 이동/이름 변경은 포함하지 않으며, 실제 제어는 필요한 관찰/결과 확인과 PRD-0008 조건을 갖춘 후속 경계다.

FEAT-0006은 승인한 아케인 중앙 감독 시전, 실제 버프 후 HUD 판독, 공통 단계/효과 확인과 벨트 닫힘 계약을 추가했다. 생명력 최대 895→1490→1580, 마나 최대 1075→1543 변화는 실제 자료다. 기존 자동 실행기에는 연결되지 않았고 주변 안전/효과 판독 생산, 자동 회복/종료·소모/획득 확인과 선점은 남아 있으므로 전체 PRD는 완료가 아니다.
