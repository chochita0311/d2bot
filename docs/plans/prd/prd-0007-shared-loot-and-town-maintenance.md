## Request Summary

서모너 런에서 시작하되 이후 디아블로 런도 사용할 수 있는 전리품 회수·참 감정/판정·보급·용병 부활의 공통 요구를 정의한다. 필드에서 자원을 소모한 결과가 다음 방의 출발 조건에 반영되어야 한다.

## Product Intent

사용자는 각 런에서 필요한 아이템과 자원 기준을 설정하고, 실제 획득·감정·보관·폐기·보급 결과를 확인할 수 있어야 한다. 자원이나 용병이 준비되지 않은 상태에서 다음 방을 시작하지 않는다.

## Confirmed Scope

- 공통 판단은 지상 라벨/접근/획득, 인벤토리/툴팁, 감정 상태, 보관/폐기, 벨트/문서, NPC 보급/부활, 결과 확인을 포함한다. 런은 목표·정상 복귀 지점·원하는 항목을 제공하고 캐릭터는 생존/버프/키/자원 기준을 제공한다.
- 기본 Resurrection Flash의 초기 회수 정책은 증오의 열쇠, **Ist/Gul/Vex/Ohm/Lo/Sur/Ber/Jah/Cham/Zod**(이스트/굴/벡스/오움/로/수르/베르/자/참/조드), 스몰/그랜드 참, 유니크 반지/목걸이다. 한국어 실제 라벨과 내부 이름의 대응도 사람이 확인한다. 일반 룬 아이콘 검출만으로 이스트 이상임을 확정하지 않는다.
- 작은/큰/거대 참의 외형/종류 확인과 감정 후 옵션·수치 판정은 분리한다. 초기 회수는 스몰/그랜드이며 라지참은 제외한다. 미감정 그랜드참은 지상에서 스킬 옵션을 알 수 없으므로 회수·감정 후 판정한다.
- 참 판정 결과는 보관/버리기/판정 불가다. 아래 사용자 확인 조건을 첫 기준으로 삼으며, 다른 종류/옵션은 이후 규칙으로 추가할 수 있다. 정답 기준이 없거나 옵션을 다 읽지 못한 참은 자동으로 버리지 않는다.
- 불필요하다고 확정한 이번 회수 참은 안전하게 판정 가능한 첫 시점에 바로 버리고 실제 제거를 확인한다. 필드 감정/폐기가 위험하거나 HUD 관찰을 가리면 안전 복귀 후 처리한다.
- 기존 사용 중인 참·장비·열쇠·룬·문서는 보호한다. 버릴 대상이 이번 회수 항목임을 확인하고, 슬롯 이동/정렬 후 이전 좌표로 다른 아이템을 버리지 않는다.
- 버린 아이템을 다시 줍는 반복을 방지한다. 버리기 판정·위치가 변하거나 불확실하면 다시 인식하며, 모든 같은 종류 참을 영구 무시하는 방식은 허용하지 않는다.
- 미확인 참은 감정 수단과 잔량을 확인한 뒤 감정 결과/툴팁을 다시 읽는다. 소비 문서가 부족하면 조건부 회수 또는 마을 보충을 요청한다.
- 감정 스크롤/문서와 귀환 스크롤/문서를 별개로 관리한다. 필드에서 필요한 스크롤은 안전하게 줍고 실제 잔량 증가를 확인하며, 마을에서는 부족 자원을 승인 목표까지 보충한다.
- 생명력/마나가 고갈되기 전에 회복하고 비상 탈출한다. 벨트의 종류·열별 잔량·예비 물약, 감정/귀환 잔량, 인벤토리 모양/공간을 다음 출발 조건에 포함한다.
- 용병 생존과 단순 화면 가림/초상화 숨김을 구분한다. 사망을 확인하면 필드 진행을 보류하고 안전 복귀 후 기존 용병을 부활시킨다. 부활 메뉴 클릭 후 실제 용병 복귀를 확인한다.
- 부활/보급에 필요한 골드, NPC 도달·대화, 구매/부활 실패와 자금 부족을 다룬다. 실패하면 다음 방을 시작하지 않고 인계한다.
- 보관할 열쇠/룬/참/유니크 장신구는 승인된 보관 위치로 옮기고 결과를 확인한다. 유니크 반지/목걸이는 초기에는 보관 대상으로 두고 추후 옵션 규칙이 생기기 전 임의 폐기하지 않는다. 사용 중인 참을 보관해서 생존 상태를 바꾸는 행동과 새 전리품 보관을 혼동하지 않는다.
- 보관 시점은 총 빈 칸 수만으로 판단하지 않는다. 보호/작업 영역 안에 다음 회수 후보가 실제로 들어가는 연속 공간과 열쇠 회수용 여유를 확인하고, 확보할 수 없거나 미감정 대기량이 상한에 도달하면 안전한 재정비를 요청한다.
- 보관함의 지정 탭/공간이 부족하면 다른 탭이나 기존 보관물을 임의 정리하지 않고 인계한다. 보관 이동·참 폐기·감정 후 슬롯 배치가 바뀌면 남은 대상을 다시 확인한다.
- 새 아이템 종류·옵션·최소/최대 수치·AND/OR 조건·런/캐릭터 예외·보관/폐기 정책을 데이터로 확장할 수 있어야 한다. 사용자는 규칙별 판정 이유와 버전을 확인하며, 한 런에서 룰을 추가하기 위해 다른 런의 이동/전투 흐름을 바꾸지 않는다.
- 정상 런 종료, 자원 부족, 인벤토리 부족, 용병 사망이 같은 재정비 판정을 사용한다. 중간 복귀 후 같은 방 재개 여부와 경로 재합류는 별도 승인 조건이다.
- 서모너의 Act 1 정상 마감에서 확인한 재정비를 첫 검증 대상으로 삼는다. 다른 런은 같은 결과 의미와 보호 규칙을 사용하되 실제 NPC/보관 UI/귀환 경로는 별도 자료로 검증한다.

## Excluded Scope

- 현재 디아블로 런 구현 또는 모든 Act NPC 자동화.
- 게임 계열 사이 캐릭터/아이템 이동, ROTW 보관 UI가 기본 Resurrection과 같다는 가정.
- 시세/거래 가치 자동 판단, 경매/거래, 임의 장비 교체·용병 재고용.
- 사용 중인 아이템 정리, 승인되지 않은 판매/폐기, 판정 불가 상태의 자동 버리기.
- 코드 패키지 이동·리팩터, 이번 초안에서 설정/기능 변경 및 실제 아이템 폐기.

## Initial Keep Rules

다음은 사용자가 확인한 **첫 보관 기준**이다. 각 수치는 감정 후 현재 툴팁에서 읽으며, 경계값도 포함한다. 알려진 비보관 조건과 읽지 못한 조건은 구분한다.

| 규칙 | 보관 조건 | 혼동하지 않을 것 |
| --- | --- | --- |
| SC-MF | 스몰참의 마법 아이템 발견 확률(MF) **7%** | 추가 옵션이 없어도 보관 |
| SC-RES-L | 스몰참의 번개 단일 저항 **11%** | 화염/냉기 11%만으로는 이 규칙 불충족 |
| SC-RES-P | 스몰참의 독 단일 저항 **11%** | 다른 보관 규칙을 만족한 참까지 버리는 거부 규칙이 아님 |
| SC-DAMAGE | 스몰참의 툴팁상 **최대 번개 피해 70 이상** | 최솟값·평균·접두/접미를 중복 합산한 값이 아님 |
| GC-LIGHTNING | 그랜드참의 **원소술사 번개 기술 +1 AND 생명력 +30 이상** | 단순 번개 피해나 다른 직업 스킬이 아님 |
| GC-JAVELIN | 그랜드참의 **아마존 투창과 창 기술 +1 AND 생명력 +30 이상** | 활/패시브 기술이 아님 |
| UNIQUE-JEWELRY | 유니크 반지 또는 목걸이 | 레어/세트/일반 장신구를 같은 것으로 보지 않음; 초기 보관 |

스몰참은 SC 규칙 중 **하나라도** 만족하면 보관한다. 그랜드참은 두 GC 규칙 중 하나를 만족해야 한다. 모든 관련 옵션을 확실히 읽었고 보호/예외에 해당하지 않는 이번 회수 참이 어느 보관 규칙도 만족하지 않으면 버리기 후보가 된다. 화염/냉기 저항이 붙어 있어도 MF 7% 등 다른 보관 조건을 만족하면 보관한다.

## Constraints

- 화면 기반 관찰과 일반 입력만 사용한다. 새 요구를 이유로 내부 아이템 데이터를 읽지 않는다.
- [PRD-0004 생존](prd-0004-summoner-survival-and-buffs.md)이 필드 감정/줍기보다 우선이다. 위험한 상태에서 인벤토리와 툴팁을 열어 안전 관찰을 가리지 않는다.
- 현재 `ignore_labels`에는 감정/귀환 스크롤과 물약이 있고 `identify_before_drop`는 false다. 새 요구와의 차이를 승인된 설정/판정 기능에서 해소해야 하며 이번에는 변경하지 않았다.
- 용병 초상화 미검출, 툴팁 일부 OCR, 슬롯 개수 추측만으로 사망/폐기/보급 완료를 선언하지 않는다.
- 사용자 승인 보관 기준을 충족한 참이나 판정 불가 참을 버리는 오판정은 0이어야 한다. 버리기 후보는 입력 없는 판정과 사람이 본 정답을 먼저 통과해야 한다.
- 기본 Resurrection에서 첫 검증을 하고 다른 계열/런은 범위와 데이터 차이를 명시한다. 공통 의미를 정하는 작업과 파일 배치 리팩터는 독립이다.

## Candidate Features

- Foundation 후보: 공통 전리품 결과·보호 영역·정책 우선권 계약.
- Product 후보: 이스트 이상 룬과 참 종류 인식/획득; 유니크 장신구는 별도 검토.
- Foundation 후보: 사용자 참 보관/버리기 기준과 판정 불가 계약.

미승인 후보이며 각각 한 가지 확인 가능한 결과로 나눈다. 다른 런 전체 구현을 하나의 공통화 기능에 흡수하지 않는다.
