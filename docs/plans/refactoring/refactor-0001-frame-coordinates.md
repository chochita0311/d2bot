# REFACTOR-0001: 캡처 기준 좌표와 실제 창 좌표

## Purpose

분할 화면에서도 같은 게임 화면 비율을 유지하면 창 크기에 맞춰 기존 판독과 입력을 연결한다. 2026-10-18 사용자가 전체 좌표 정규화와 공통 계층 배치를 승인했다. 실행 이력은 [통합 run](../run/run-20261009-07-summoner-live-integration.md)이 소유한다.

## Refactor Type

- Primary type: `Behavioral`, 공통 좌표 인터페이스 추가.
- Parity target: 기존 기준 크기의 판독·입력 보존, 다른 크기 지원은 의도한 변경.
- Compare baseline: 기존 634검사 통과 작업 트리. HEAD `db325c4c2b236a5796d5db911422afa8565c56c5`에는 진행 중인 변경이 포함되지 않으므로 전체 동등성은 `Provisional`이다.

## Scope

공통 `common` 계층이 게임 내용 영역의 기준/실제 좌표 변환을 소유한다. `ScreenCapture`는 설정한 레이아웃으로 캡처를 정규화하고 물리 창 경계는 그대로 제공한다. 판독기는 기준 좌표를 사용하고 입력 생산자는 공통 변환을 호출한다. 마을, 이동, 전투/줍기, 협곡, 조합/일반 줍기, CLI 판독과 진단을 연결한다.

## Non-Goals

전투 끄기, 판독 임계값 일괄 완화, 새 그래픽/언어 자산, 감지 우회, 게임 내부 상태 접근, 다른 화면 비율을 억지로 변형하는 지원은 제외한다. 기존 런 실패 수정과 새 방 성공은 이 변경의 입력 없는 검증과 구분한다.

## Invariants

- 실제 창 원점·크기는 캡처 메타데이터로 유지한다. 캡처 시점의 기하와 이후 입력 시점의 기하가 다르면 오래된 좌표를 전송하지 않는다.
- 게임 내용과 OS 제목 표시줄/테두리를 별도 변환한다. 기준 좌표의 현재 판독·250ms 시한·실제 포인터 확인·중단/정리·생존/버프 조건은 유지한다.
- 마을의1267×753 판단 좌표→캡처 기준 좌표→실제 화면 변환은 각각 한 번이다. 실제 포인터를 지형과 비교할 때에는 역변환한다.
- 공통 `desktop_to_frame`은 영상 crop에 사용할 정수 픽셀을 반환한다. 순수 `FrameGeometry.from_desktop`의 연속 좌표 계산과 구분한다.
- 기준 레이아웃과 실제 창/내용 영역이 같으면 픽셀과 좌표를 그대로 유지한다. 다른 크기의 템플릿 정확도는 별도 검증 전 보장하지 않는다.

## Planned Work

### Step 1 — 공통 기하와 캡처

Goal: 순수 좌표 변환, 레이아웃 자료, 표준 Windows client 경계 연결.

Why this grouping: 판독/입력 양쪽이 같은 기하를 써야 중복 배율과 DPI 오차를 막는다.

Guardrails: 화면 비율 오차 한도 밖에서는 입력 전 거부하고, 지역/몬스터 규칙은 공통 모듈에 넣지 않는다.

Targets: `common/frame_geometry.py`, `common/capture.py`, capture 설정, 공용 UI 레이아웃.

Validation: 기준 크기 무변환, 크기/제목 표시줄 변화, 음수 원점, 왕복 좌표, 비율/기하 변경 거부.

Exit gate: 순수 검사와 실제 현재 창의 입력 없는 캡처가 통과한다.

### Step 2 — 입력 생산자 연결

Goal: 모든 기존 화면 좌표 입력과 역방향 포인터 비교를 공통 변환으로 연결한다.

Why this grouping: 캡처만 바꾸면 입력이 잘못된 위치로 간다.

Guardrails: 기존 물리 입력 backend의 경계·포커스·전송/포인터 확인은 유지한다. 기존 마을 비율 변환을 중복 적용하지 않는다.

Targets: Summoner 실행기, 공통 줍기/호버, 마을 lifecycle, 조합/일반 줍기, core bot, 진단 및 search runtime. 실제 포인터 전송은 공통 가상 데스크톱 dispatcher를 사용해 다른 모니터/음수 원점에도 같은 물리 좌표를 전달한다.

Validation: 대표 이동/호버/아이템/메뉴 좌표의 실제 왕복과 기준 크기 회귀, compile/Black/전체 unittest, 변경된 좌표 연산 검색 감사.

Exit gate: 누락된 입력 경로 없이 검사 통과 후 안전한 새 방에서 실제 진입/입력/Act1 마감을 확인한다.

## Validation Gates

기하 단위 검사→소비자 회귀→전체 unittest→입력 없는 현재 창 판독→감독 GUI 실행 순서다. 저장 화면을 축소/복원한 판독은 실제 작은 창 정확도나 새 방 성공을 대신하지 않는다. 실제 좌표와 기준 좌표, 원래 캡처 기하는 보고서에 구분한다.

## Intentional Deltas

설정한 레이아웃이 있는 window 캡처는 기준 크기 프레임을 내보낸다. 내용 영역의 비율이 허용 오차1% 밖이면 거부한다. 레이아웃 미설정/모니터·영역 캡처는 기존 native 동작을 유지한다.

## Risks / Open Questions

축소 시 텍스처/작은 글자 정보가 사라질 수 있고, 게임 UI 자체 배율 설정 변경은 같은 해상도 비율만으로 해결되지 않는다. 제목 표시줄 DPI 차이는 client 영역으로 분리한다. 실제 다른 크기와 분할 화면에서의 성공 실적은 아직 없다.

## Exit Goal

공통 변환 한 곳으로 판독과 실제 입력이 일치하고 기존 안전 조건을 통과한다. 그 뒤 통합 run의 최근3회 실패 보완과 북쪽10회 연속 검증을 이어간다.

Step1/2의 공통 캡처·정/역변환과 기존 입력 소비자 연결은 구현됐다. 전체702개 입력 없는 회귀와 기준 크기의 후속 GUI70/72 빈 북쪽 방 마감을 확인했으나 이 성공만으로 좌표 변경의 단독 효과를 확정하지 않는다. 축소 재생·실제 작은 창의 부분 관찰/입력과 작은 창 전체 완주는 구분하며, Step2의 작은 창 완주 검증은 남아 있다. 최신 상태·payload 경계·재개 순서는 [통합 run 세션 인계](../run/run-20261009-07-summoner-live-integration.md#session-handoff-20261020)가 소유한다. 비교 기준의 `Provisional`은 해제하지 않는다.
