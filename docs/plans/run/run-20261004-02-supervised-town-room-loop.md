## Current Loop State

선택→Hell→Act 1→실제 WP→Act 2 마을→Act 1→저장 종료→선택 확인을 구현했다. `TownLoopPlanner`가 최신 화면으로 행동을 결정하고 `RunLifecycleSession`이 실행한다. Act 1은 시간 상한이 있는 왼쪽 홀드 중 관찰하고, 목표가 보이면 해제한 다음 프레임에서 재인식하여 클릭한다. 방향은 구간별로 정하며 홀드 중 커서를 계속 조정하는 연속 조향은 구현하지 않았다. Act 2도 지형/푸른 효과로 최신 발판 위치를 찾으며 총 세 번 제한으로 재접근한다.

WP 개폐 시 게임의 약 360px 커서 이동을 사용자의 직접 조작이라고 오판했던 부분을 수정했다. 예상 변위와 메뉴/도착 화면의 긍정 증거를 함께 요구한다. NPC 취소 메뉴에는 홀드 해제→Esc→재관찰을 추가했다. 창/포커스 변화·중단·인식 시간 초과는 후속 입력을 억제하고 홀드를 해제한다.

GUI의 `Live town loop (1–3 runs)`와 CLI `main.py --town-loop 1 --difficulty hell`이 같은 세션을 사용한다. [사용법](../../features/town-room-loop.md)이 private 템플릿/증거의 위치와 재검토 절차를 소유한다. `192534` 감독 실행은 Flash 선택 화면에서 끝났다. `2026-10-05` 세션 종료 시 Idle 상태의 프로젝트 GUI를 닫고 프로젝트 Python 프로세스가 남아 있지 않음을 확인했다.
