## Implementation Boundary

현재 창의 실제 화면을 먼저 확인한다. 생성은 Play→Hell→Act 1 마을 확인, 이동은 웨이포인트 메뉴의 Act 2→루트 골레인 확인, 복귀는 메뉴의 Act 1→자매단 야영지 확인, 종료는 Save and Exit→캐릭터 선택 확인이다. 로딩이 짧아 캡처되지 않더라도 목적 상태의 긍정 증거로 완료할 수 있다. 잘못된 메뉴/목적지/화면은 제한 대기 후 입력을 중단한다.

좌표는 인식된 버튼/패널 및 최신 창 영역을 기준으로 계산한다. 정규화나 템플릿 스케일은 캡처 크기와 함께 일관되게 적용한다. Act 1의 실제 웨이포인트를 찾은 뒤 클릭하며, 미니맵 마커를 세계 좌표로 직접 클릭하지 않는다. 사용자 추가 관찰에 따라 오른쪽 접근 두 지형 및 시작점 1시 배치를 대상으로 한다. 이동은 시간 상한이 있는 왼쪽 버튼 홀드와 최신 화면 관찰을 결합한다. 목표가 보이면 홀드를 해제하고 다음 프레임에서 위치를 다시 인식하여 클릭한다. NPC 대화는 별도 긍정 증거로 닫고 재접근하며 횟수를 제한한다. 중단·오류·포커스 상실 시 홀드는 반드시 해제한다.

캡처, 인식, 입력 시간과 관찰→입력 지연을 기록한다. 불필요한 고정 이동 대기 및 입력 장식 지연을 없애되 메뉴/도착의 긍정 확인은 유지한다. 포인터 불일치는 예상·관측 좌표를 기록하며 사용자 직접 조작이라고 단정하지 않는다.

Act 2 복귀도 지역·HUD·발판 주변 지형 및 푸른 효과의 긍정 증거로 클릭한다. 메뉴가 열리지 않으면 최신 프레임에서 재인식하여 총 세 번까지만 접근한다. NPC 메뉴가 확인되면 닫고 다시 관찰한다. 처리 완료 후 캡처·핫키를 해제하며 정리 오류가 세션의 실행 상태를 고정시키지 않도록 한다.

기존 세션에 유한 town-loop 경로를 추가하거나 별도 소규모 세션을 구성할 수 있다. 기존 room-only 모드는 유지한다. 공통 인식·입력 helper의 변경은 기존 소비자도 확인한다. 중단 이벤트를 클릭 직전과 이동 완료 직후 확인하여 중단된 이동 뒤 클릭하는 경로를 차단한다. 포커스·창 크기/위치·캡처 이상은 입력 전에 확인하고 대기/중단으로 처리한다.

## Evidence And Validation

- 원본 프레임·상태/입력 이벤트·결과: ignored `recordings/summoner/evidence/<session-id>/`.
- 런 메타데이터·판정·한계: canonical run/evaluation 문서.
- 개발자료의 소유·보존·세션 종료 처리는 [개발자료 정리 기준](../../project/developer-guide.md#evidence-handling)을 따른다. 이 계약의 검증 요약·한계와 실제 정리 결과는 연결된 run/evaluation에 남긴다. 자산/manifest 참조를 유지하고 미검증 복구·전체 PRD 수용을 완료로 바꾸지 않는 것이 세션 정리의 보존 조건이다.
- 반복은 먼저 1회, 통과 후 최대 3회. 총 15분을 초기 상한으로 하고 오류 시 멈춰 수정한다. 온라인 생성 제한/연결 오류를 만나면 즉시 중단한다.
- 테스트는 인식·좌표·중단에 의미 있는 회귀 케이스와 직접 화면 관찰을 사용한다. 실제 런 성공, 코드 검증, 미검증 안전 시나리오를 구분한다.
- 아케인 입구 방문은 별도 시도로 기록하며, 그 지역에서 탐색·전투를 시작하지 않는다. 도착 시 즉시 웨이포인트로 마을 복귀하거나 안전 종료한다.

## Current Assumptions

선택 화면의 Flash를 육안 확인했고 온라인 탭이 활성이다. Hell은 기존 세션의 기본값을 유지한다. 다른 캐릭터/모드 선택은 자동화하지 않는다. 현재 창의 DPI·그래픽 상태는 캡처에서 확인하여 실행 증거에 기록한다. 생존·버프·전리품 관련 PRD는 이번 승인에 포함되지 않는다.
