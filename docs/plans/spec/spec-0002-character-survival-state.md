## Source And Ownership

사용자의 승인·Flash 값·필드 전용 버프·최근 순서가 기준이다. `config/characters/characters.json`은 캐릭터 정책을 소유하고 공통 모듈은 검증·확인된 상태·판단을 소유한다. 현재 Arcane 입력 재생과 마을 세션을 새 판단기에 연결하지 않는다.

## Configuration Contract

`CharacterProfile.survival`은 선택적 정책이다. 누락은 `None`이며 다른 캐릭터나 런의 생존 수치를 대신 가져오지 않는다. 정책은 체력/마나 사용 비율, 포션 종류, 보충 진입 잔량, 고갈 종료 여부, 벨트 확인 키, 열별 사용 키/종류/수용량/목표량, 이름/키/지속시간/갱신 여유를 가진 버프 목록이다.

비율·시간은 유한한 숫자이며 bool을 숫자로 받지 않는다. 비율은 (0,1], 지속시간은 양수, 여유는 [0,지속시간), 수용량/목표량/보충 기준은 유효 정수다. 열 번호/버프 이름 중복과 미지원 필드는 오류다. TP 목표량처럼 미확정 값은 null로 두고 해당 방의 최초 실제 관찰량을 보충 기준으로 사용한다.

Flash는 포션 3열×4개 목표, 4열 TP, 체력 0.5/마나 0.1, 보충 6개 이하, 0개 종료, backtick, 전투 지시 150초/10초 여유를 갖는다. 입력 순서는 `w,a,a,s,f1,d,w`다. 다른 프로필은 기존 입력/메타데이터를 유지한다.

## State Contract

- tracker는 한 캐릭터·방·정책에 귀속한다. 새 방이나 캐릭터에는 새 tracker를 사용한다.
- 관찰 stamp는 캐릭터·방·sequence·monotonic 관찰 시각을 포함한다. 벨트 관찰/결과는 한 증가하는 흐름, 각 버프 확인은 버프별 흐름을 사용한다. 중복·과거/시각 역전·다른 context는 무시한다.
- 벨트는 모든 설정 열의 실제 종류와 개수를 받아 초기화한다. 미관찰·예상 종류 불일치·수용량을 넘는 결과·수동 변경은 상태를 불명확으로 만들고 새 관찰을 요구한다. 확인된 사용/획득 delta만 계산하며 기록은 정책 크기 안에서 유지한다.
- 버프는 필드에서 주변 적 없음이 확인된 실제 시전 시각으로 기록한다. 요청/토큰 전송/중단·마을 확인은 타이머를 갱신하지 않는다. 시간은 누적 실행 횟수가 아닌 절대 monotonic 차이로 계산한다.
- 판단은 최신 HUD/위치/주변 안전 관찰, 현재 시각, 호출자가 정한 화면/벨트 유효 시간 상한을 받는다. 상한은 실게임 기본값으로 임의 확정하지 않는다. 누락/늦은 상태는 `hold`, 확인된 0개는 `exit`, 낮은 체력/마나는 `use_potion`, 안전한 필드의 버프 미확인/갱신 필요는 `buff`, 부족 자원은 `replenish`, 준비된 상태는 `continue`다.
- 고갈은 HUD 수치 미관찰보다 우선하되 유효한 같은 context의 관찰을 요구한다. 회복은 버프/보충보다 우선하며 두 비율 조건이 동시에 참이어도 한 포션 요청이다. 미확인/만료 버프의 필드 진행을 허용하지 않는다. 마을 또는 적 있음/안전 불명은 버프 요청을 만들지 않는다.
- 결과는 요청·이유·사용 키·필요 버프·열별 결손/보충 필요를 제공한다. 실제 입력·종료 성공·완전 생존·전투 모드 해제의 증거가 아니다. 실제 키 전송·소모 확인·재사용 간격은 후속 소비자 소유다.
