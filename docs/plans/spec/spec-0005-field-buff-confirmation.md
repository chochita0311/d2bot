## Contract

개인 입력 순서와 공통 확인 상태를 분리한다. 트랜잭션은 한 캐릭터/방에서만 동작하며 최신 화면과 명시적 안전 필드/주변 적 없음 근거를 요구한다. 미확인은 안전이 아니다. 단계 요청·전송 확인·효과 확인을 별개로 다루며 중단 이후 자동 재개하지 않는다.

현재 감독 검증은 아케인 중앙을 육안으로 확인한 뒤 한 입력/새 관찰 순서로 수행했다. 최대 생명력/마나 증가는 전투 지시 효과 후보이며 다른 효과/무기 교체와 혼동하지 않도록 스킬/상태/복귀 자료를 함께 대조한다. 모호한 효과는 미확인으로 남긴다. 제품 자동 판독기가 필드/주변 적 없음까지 증명한 것으로 취급하지 않는다.

벨트는 관찰의 시작/완료/닫힘 확인 상태를 추적한다. 펼친 동안 또는 닫힘이 미확인이면 일반 이동을 보류한다. 토글 키를 보냈다는 이유만으로 닫힘을 확정하지 않는다. 기존 HUD 판독의 `not_verified_expanded`는 닫힘의 긍정 증거가 아니므로 별도 closed 증거가 필요하다.

버프 타이머는 실제 해당 시전의 보수적 시작 시각을 사용한다. 마지막 단계/확인 지연을 시전 시각으로 사용하지 않는다. 이 기능의 제품 코드는 입력 없는 트랜잭션/증거 소비를 기본으로 하며 기존 무조건 키 재생 실행기를 대체해 자동 필드 진행을 허가하지 않는다.

## Implementation And Producers

- [BuffSequence/BeltInspection](../../../diablo2/common/buffing.py): 개인 순서의 요청→전송 결과→시각 확인을 분리한다. 단계 실패/시작 후 안전 차단은 취소하며 자동 재개하지 않는다. 효과·전체 순서·개인 전투 장비 복귀의 명시적 확인 뒤에만 원래 요청 직전 관찰 시각을 FEAT-0003에 전달한다. 같은 생산자의 단조 시각/순번을 요구하고 갱신 시점이 지난 완료 상태를 진행 허가로 재사용하지 않는다.
- [시각 보조](../../../diablo2/common/buffing_vision.py): 최대값 증가 후보와 열린 인벤토리의 I/II 탭만 읽는다. 후보는 버프 종류/전체 효과를 증명하지 않으며 탭은 개인 전투 세트/장비/FCR를 추측하지 않는다. 현재 전체 효과·필드/주변 안전 증거 생산자는 감독자다.
- [HUD 판독](../../../diablo2/common/survival_vision.py): v2 manifest의 제한된 라벨 검색/마나 변형으로 실제 네 자리 최대값을 읽는다. 닫힘 전용 테두리를 확인해 `belt_visibility`를 반환한다. 펼침 미검출만으로 닫힘을 선언하지 않는다. 펼친 잔량 확인 뒤 `BeltInspection`은 최신 닫힘과 공통 생존 조건이 있어야 이동 조건을 통과시킨다.
- 공통 자료: [HUD owner](../../../assets/ui/survival/README.md), [무기 탭 owner](../../../assets/ui/weapon-set/README.md). 이름/장비 원본을 공통 자산에 넣지 않는다. 기존 자산의 이동/개명/형식 교정은 제외한다.

## Validation

현재 native 배치의 실제 중앙·버프 전/중/후·벨트 열린/닫힘을 대조한다. 다른 캐릭터/방·시각 역행·안전 불명확·적 접근·중단·순서 누락/중복 확인·효과 불명확을 합성으로 확인한다. 실제 위험/저체력을 만들지 않으며 감독과 자동 readiness를 구분한다. 공유 자료에는 개인 이름을 넣지 않고 task 원본은 필요한 crop/결과를 보존한 뒤 정리한다.

실제 감독 입력과 여러 독립 Python 캡처 프로세스 사이에는 정확한 공통 단조 시계가 없다. 실제 입력의 정밀 시전 타이머/150초 지속 측정을 주장하지 않고, 제품 시간 계약은 단일 시계 영역의 합성 관찰로 검증한다. 자세한 운영 계약은 [필드 버프 안내](../../features/field-buffs.md)가 소유한다.
