## Execution Contract

공통 제어기는 캐릭터/방/순번/시각이 맞는 관찰과 확인된 생존 상태를 소비한다. 관찰 생산자는 현재 위치·벨트 닫힘·살아 있는 적의 근접 판정·이동 목표 도달 가능·정리 확인·전리품 확인을 각각 명시한다. 템플릿 후보 또는 미검출을 확정값으로 대신하지 않는다. 최신성/시간 상한은 호출자의 명시적 설정이고 실제 반경 기본값을 추가하지 않는다.

우선순위는 중단/포커스 상실→확인된 포션 고갈→최신성→회복→버프 갱신→벨트→전투→전리품→이동이다. 포션 0개는 화면 없음/오래됨에도 방에 연결된 확인 상태로 종료 요청을 유지한다. 종료 요청은 Esc 메뉴 확인/실제 게임 종료 확인과 구분한다. 포션 입력은 1회만 보내고 확인된 소비/회복이나 벨트 재관찰 전까지 후속 입력을 막는다. 입력 실패/미확인 결과를 소비 성공으로 기록하지 않는다.

F2/F4는 단일 소유자가 관리한다. 다른 키를 누르기 전 현재 유지 키를 해제한다. 입력 실패는 모든 소유 키 해제를 시도하고 종료 상태로 둔다. 독립 watchdog은 화면 시한, 최단 버프 갱신 시각, 전투/도착 시한에서 키를 놓으며 미래 관찰이나 재사용 프레임으로 lease를 연장하지 않는다. pause/stop/worker exception에서도 release를 수행한다. backend는 key_down/key_up/move/press의 짧고 비차단인 구현을 제공해야 한다; OS/프로세스 정지까지 복구를 보장하지 않는다.

전투가 끝났다고 확정된 뒤 전리품 관찰 단계를 거친다. 정리 또는 전리품이 미확인이면 F2를 재개하지 않는다. 생존 감시는 이 단계에도 유지한다. 자원 보충 진입은 캐릭터 정책(Flash <=6)이고 실제 획득/잔량 갱신으로만 보충한다.

텔레포트 조준 변경은 직업/FCR 카탈로그의 프레임/25초를 하한 참고로 사용하며 실제 확인된 도착 지연의 이동 평균으로 느려질 수 있다. 유지 이동에서는 간격마다 키를 재전송하지 않고 조준만 갱신한다. 도착 미확인/정체는 설정 상한에서 해제한다. 카탈로그를 실측 프레임으로 부르지 않는다.

## Integration And Verification

공통 코드에는 게임/런 직접 import를 넣지 않는다. 주입형 backend와 latest-observation mailbox를 두어 저장/무거운 비전과 제어를 분리하고 기본은 dry-run이다. 기존 북쪽 시험의 적/전리품/쿨다운 반환과 stale-fast 경로에서 키가 남는 오류를 수정한다. 새 제어기를 자동 안전 생산자가 없는 기존 경로에 무조건 활성화하지 않는다.

runtime은 같은 프레임의 HUD/scene을 소비한다. 현재/최대값과 긍정 벨트 표시는 HUD에서 가져오고 안전/적/도착 의미는 별도 생산자가 검증한다. 새 펼친 벨트의 절대 잔량은 미확인 포션 요청을 해소하되 소비 delta를 다시 더하지 않는다. 소비 시점에 오래된 큐 항목은 잔량을 덮어쓰지 않는다.

공통 연속 버프 실행기는 프로필 순서·키 간격과 명시적 시간 상한을 소비한다. 관찰/입력/중단 가능한 대기/시계는 주입하고 매 키마다 사람의 확인을 요구하지 않는다. 위험/고갈/미확인/중단은 남은 키를 취소하며 전송 완료는 효과나 장비 복귀를 확정하지 않는다. 표준 키 입력 backend는 SendInput 성공 반환값을 검사하고 짧은 press는20ms keyDown/keyUp과 finally 해제를 사용한다. 장비 복귀 확인과 실제 효과 수용은 소비자의 별도 책임이다.

Contract: 잘못된 방/순번/시각·중복 프레임·열린 벨트·불확실 사망·입력 실패·저장/비전 지연을 확인. Functional: 가짜 입력으로 유지/전환/포션 대기/0개 종료/140초 독립 해제/전리품 후 이동/도착 적응을 통합 검증하고 기존 회귀를 실행. 실제 창 크기/도구 입력 지원이 부족하면 live 결과는 미검증으로 남겨 FC-06을 지킨다.
