## Execution Contract

이 spec은 최초 공통 비차단 확인 경계와 당시 감독 진단을 보존한다.2026-10-11 후속 승인에 따라 정상 GUI/main은 감독 JSON/I 없이 현재 안전 관찰로 순서를 전송하고 실제 S 요청+140초에 갱신한다. 전송은 `dispatched_unconfirmed`, 전체 효과는 `not_independently_verified`이며 제때 갱신의 실제 게임 검증은 남아 있다. 이 최신 실행 정책과 아래 확인 API의 계약을 구분하며 현재 구현·다음 검증은 [통합 run Attempt15](../run/run-20261009-07-summoner-live-integration.md#attempt15-세션-마감-정리와-다음-gui-실행-인계)가 소유한다.

`FieldControlRuntime`의 선택적 버프 소비자가 공통 `BuffSequence`를 비차단으로 진행한다. 기본 backend는 dry-run이다. 실제 사용자는 동일한 방/시계 영역의 새 scene 생산자와 단계 응답용 `next_stamp`를 제공한다. 확인되지 않은 주변 안전이나 효과를 runtime이 만들어 내지 않는다. 화면/벨트 유효 시간은 기존 `FieldLimits`, 순서/간격은 캐릭터 actions, 실행/효과 확인/안전 대기 상한은 명시적 양수 설정에서 가져온다. 실게임 운영 기본값을 추측하지 않는다.

갱신 전에는 기존 필드 판단을 소비한다. 버프 필요 시 일반 유지 입력을 해제하고 최신 안전 관찰을 요구한다. 안전 확보 대기에도 상한을 두며, 시한을 넘기거나 화면/포커스/방/시계가 무효면 검토 상태로 고정하고 새 실행 객체 전까지 일반 입력을 재개하지 않는다. 회복과 확인된 고갈은 버프보다 우선한다.

시퀀스가 시작되면 한 pump에서 최대 한 토큰만 전송한다. 다음 토큰의 최소 시각까지 sleep하지 않고 다음 관찰을 기다린다. 간격 중에도 안전을 검사한다. 각 전송 직전 포커스·중단·현재 화면의 나이를 다시 확인한다. 같은 프레임으로 두 토큰을 보내지 않는다. 응답 stamp는 요청보다 새 순번이고 실제 단조 시계의 시각이며, 다음 관찰도 그 이후여야 한다. 실행 상한은 시퀀스 전체에 적용한다.

최소 키 간격은 실제 backend 응답 시각부터 계산한다. 전송 도중 큐에 들어와 응답보다 오래된 프레임은 다음 단계에 쓰지 않고 새 관찰을 기다린다. 이를 새 생존 관측으로 집계하여 감시 시한을 연장하지 않는다. actor lock이 pump/pause/stop을 직렬화하고 별도 중단 신호가 다음 전송을 차단한다.

마지막 토큰 이후에는 새 프레임과 같은 stamp의 `BuffConfirmation`을 별도 mailbox 항목으로 받는다. 효과/전체 순서/장비 복귀를 모두 확인한 경우에만 `BuffSequence.confirm_effect`를 호출한다. 확인 대기도 상한을 가지며 실패·늦은 확인·다른 방·과거 프레임은 타이머를 갱신하지 않는다. 다음 갱신은 확인 시각이 아니라 해당 버프 입력 요청 직전 관찰에서 계산한다.

pause/stop/focus loss/worker 예외는 진행 중 순서를 취소한다. 부분 전송 뒤 장비 복귀를 추측하거나 자동 w 재전송하지 않는다. 회복/종료 요청은 기존 필드 루프로 한 번 전달하되, 취소된 버프는 자동으로 다시 시작하지 않는다. 검토 사유를 노출하고 유지 입력을 해제한다. 실제 안전 종료 완료는 별도 소비자의 관찰 책임이다.

## Verification

가짜 시계와 dry backend로 최초 시퀀스, 프로필 간격, 정확한 140초 경계, 다음 갱신, 오래된/중복/미래 관찰, 키 간격 중 적 접근·벨트 열림·저자원, 포커스·pause·stop·실행/확인 상한, 불완전 시각 확인, backend 예외와 관찰 중단을 검증한다. 기존 필드 runtime의 버프 소비자 없는 동작은 유지한다. 전체 회귀·Black·컴파일·diff/문서 링크 확인을 실행한다. live 140초 갱신은 자동 안전/효과 생산자가 준비된 뒤 한 감독 시험부터 진행한다.

[RUN-20261009-07 Attempt2](../run/run-20261009-07-summoner-live-integration.md)의 `--renew-once`는 별도 준비된 감독 진단이다. 실제 S 요청+140초 감시는 수행했지만 새 안전 허가의10초 창을 넘겨 갱신 입력0회로 끝났다. 수동 확인 대기의 상한과 관찰 자료의15초 신선도를 구분하며, 이 결과를 공통 runtime의 자동 안전/효과 생산자나 실제 갱신 통과로 기록하지 않는다.

2026-10-10 당시 통합 main의 감독 개발 경로는 다음 조건으로 연결했다. 연속 구간이 버프 시한으로 끝나고 남은 개발 구간이 있으면 현재 경로 그래프를 유지한 채 입력을 해제한다. 새 `field_safety`의 근접 안전·현재 자원 안정 검사를 통과해야 전체 프로필 순서를 전송하며, 새 `initial_effect`의 효과/전체 순서/무기 복귀 확인 뒤 실제 시전 요청 시각으로 시한을 계산한다. 갱신 시 인벤토리 패널을 열거나 방을 새로 만들지 않는다. 최대8회·각 감독 대기300초·근거15초를 적용하고 부분 시전/이미 만료된 새 버프/효과 미확인은 재개하지 않는다. 이는 당시 감독 연결이며 공통 비차단 소비자의 자동 안전/효과 생산자를 대신하지 않는다. 이 수치와 JSON 절차를 현재 정상 GUI의 요구로 적용하지 않으며 후속 실행 정책은 위 최신 통합 run을 따른다.
