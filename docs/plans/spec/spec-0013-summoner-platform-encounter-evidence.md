## Contract

`ObjectiveReading.ground_point`는 접근용 현재 바닥 목표이며 도착/보스 위치/사망 근거가 아니다. 룬 경로는 [SPEC-0012 Attempt11](spec-0012-arcane-perceptual-navigation.md#contract)의 현재 서로 다른4개 이상 외형과 검토 여섯 자리의 일대일 정합을 소비한다. 모양과 자리 번호를 결합하지 않으며 .68 외형 점수·24px 정합 잔차·최다 지지의 유일한 이동 군집 조건을 유지한다. 검토 원본의 바닥 중심 `[740,560]`에 같은 현재 자리 정합의 이동을 적용한다. 일지 경로는 현재 일지 박스 하단 중심에서80px 아래를 접근 목표로 쓴다. 범위 밖 좌표는 제공하지 않는다.

`run_platform_encounter`는 현재 로브가 있으면 기존 근접/접근을 사용한다. 로브가 없고 현재 접근 목표가 멀면 현재 바닥 planner가 그 목표100px 이내를 지지할 때만 단일 F2를 요청한다. 최대2회와 기존 시전 참고 하한을 소비하고 매번 새 HUD·발·발판을 재관찰한다. 이미 근접하면 이동하지 않고 실제 호버 후 새 붉은 적 패널로 전투를 확인한다. 패널 검사에는 실제 커서 일치·250ms 화면·근접 범위를 요구하며 미검출은 clear가 아니다. 공격 OFF인 main은 이 함수를 호출하지 않는다.

현재 로브 또는 근접 적 패널 양성에서만 F4를 허용하고6초 노바/12초 전체/원래 버프 시한을 모두 지킨다. 후보/패널 소실·바닥/발 미확인·포커스 상실·중단은 입력을 해제한다. 자원 부족은 기존 resource_low 경로를 유지한다. 결과는 실제 처치 생산자 없이 kill_unconfirmed이며 자동 복귀를 승인하지 않는다.

사전 프레임은4장 ring, 전투 시작/실제 공격/최종 후속은 총24장으로 제한한다. `encounter.evidence`는 파일명·관찰 순번·단조 시계 촬영 시각·initial/prefight/combat/final 구분을 기록한다. HUD 미확인으로 입력을 보류한 프레임도 같은 순번의 관찰 행에 이유를 남긴다. 오래된 큐를 이동 제어에 소비하지 않고 현재 상호작용과 실제 전송 수를 구분한다.

## Verification

실제 접근 거부는 관찰의 처리 시각과 요청 조준·원래 촬영/만료 시각·마지막 검사 단계/이유·유효 시간을 검사한 시각/프레임 나이를 기록한다. 중단·포커스 상실·역행/250ms 경과·버프 만료·포인터 불일치를 구분하되 같은 현재 화면의 기존 허가 조건이나 시계 호출을 늘리지 않는다. 진단 없는 과거 approach_not_sent는 구체 원인이 미확인이다.

현재 바닥 목표의 랜드마크 이동, 목표 없는 파란 효과/세 룬/섞인 배치 거부, 오래된/자원 부족/시한/발 미확인 입력0회, 적 패널 미검출 공격0회, 현재 긍정 패널의 노바, 전투/버퍼 상한을 검사한다. 실제 main의 접근/노바와 처치 자료 범위를 별도로 기록한다. private 정답 자료가 없으면 독립 자료 검사를 skip으로 표시하고 실게임 정확도로 확대하지 않는다.
