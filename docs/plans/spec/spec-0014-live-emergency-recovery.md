# SPEC-0014: 비상 회복 입력과 실제 잔량 재판독

- ID: `spec-0014`; Status: `ready`; Feature: [FEAT-0015](../feature/feat-0015-live-emergency-recovery.md)
- Run: `run-20261009-07`; Attempt: `10`; Profile: `backend-product`; Evaluators: Contract, Functional

자원 부족은 같은 현재 HUD의 각 자원 현재값/최대값 비율로 판단한다.250ms 이내·포커스·중단·닫힌 벨트와 현재 보라 포션 외형이 확인된 개인 정책 열만 선택한다. TP 열/미확인 칸에는 입력하지 않는다. F2/F4를 먼저 해제하고 포션 키는 한 시도당1회만 전송한다.

새 HUD에서 낮았던 비율의 상승과 두 회복 임계값 충족을1초 안에 확인한다. 그 뒤 벨트를 펼쳐 실제16칸을 읽고 닫힌 상태를 별도로 확인한다. 전체 시도는3초·방당 최대12시도로 제한한다. 잔량은 펼친 현재 벨트에서만 갱신하며 단순 전송/색 변화/자연 회복을 포션 사용 확인으로 바꾸지 않는다. 회복·잔량·닫힘 중 하나라도 미확인이면 자동 재시도 없이 기존 resource_low 안전 종료로 돌린다. 현재 포션0개도 종료한다.

이동·목표 발판·대기 방어는 같은 consumer를 공유한다. 회복 중에는 경로/공격 입력을 보내지 않고 복귀 후 새 프레임으로 다시 판단한다. 입력 기록은 요청·회복 관찰·실제 벨트 수·닫힘을 구분하며 진단 이미지는 시도당 최대3장이다. 버프·경로 기억과 기존 시한을 임의 갱신하지 않는다.

검사는 새 최대값의 같은 비율, 경계값, 오래된/미확인/잘못된 칸/중단/포커스 입력0회,1회 전송 뒤 회복/잔량/닫힘 미확인, 실제 잔량0, 성공 후 재관찰을 포함한다. 실게임 소비는 실제 낮은 비율과 전후 HUD·벨트·전송 기록으로 따로 확인한다.
