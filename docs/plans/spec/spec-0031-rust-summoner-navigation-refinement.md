## Validation And Live Procedure

사용자가 중앙 복귀 분기는 잘못된 방향이라고 정정했다. 정상 마감은 서모너 처치 확인→일지→붉은 포탈→협곡 WP→Act1 귀환이다. 미확인/열쇠 미검출을 중앙 복귀로 보내는 분기는 제거하며 실행·배포하지 않는다. north return은 실패 복구의 기존 별도 절차로만 남긴다. 처치 확인이 실패하는 관찰·시점·외형 원인을 보완하고, 전리품 검사가 끝나면 원래 협곡 진입 계약으로 이어간다. 지도 숨김/재관찰과 입력·화면 신선도 보호는 유지한다.

R18처럼 방어 중 처치가 늦게 일어나도 감시가 끝없이 주변 호버만 하지 않도록, 이전 전용 encounter가 kill_unconfirmed일 때만 대기 감시가 이미 캡처한 화면의 현재 단상/시체 후보를 최대4Hz로 재관찰한다. 신선한 후보를 읽으면 입력 해제·probe 초기화·감시 worker 실제 종료 뒤 정식 encounter를 한 번 재실행한다. 이 신호 자체는 죽음이 아니며 새 순서 있는 시체 쌍과 정상 전리품 검사를 다시 요구한다. 재시도는 현재 갱신된 버프 시한을 사용하고 이전/재확인 보고서·증거 이름을 구분한다. 이 모드의 idle 호버는 현재 actor 후보에만 한정하고 현재 양성 위험/자원 방어는 유지한다. 닫힌 encounter pool은 성공 정리 뒤 버리고, 늦은 정리 오류 때는 기존 소유자를 보존한다.

다섯 번째3회 뒤 계단 굴곡 보정: detour가 아직 없는 현재 floor-flow에서 전방이 반대 방향이고 넓은 측면 출구가 없으면, 기존 굴곡 중 탐침과 동일하게 clearance×2(현재64px) 이상의 현재 측면 바닥을 검토한다. 측면40도·현재 바닥 clearance·실패 좌표 제외·250ms·입력 전35도 재확인은 그대로다. 넓은 출구를 먼저 고르고 짧은 후보는 `observed_corner_probe`로만 분류한다. 반대 방향 자체를 무조건 허용하거나 과거 graph port를 쓰지 않는다. R13의 현재 동쪽 바닥/반대 frontier 재생과 바닥 제거·stale·실패 제외를 검사한 뒤 실게임에서 확인한다.

네 번째3회 뒤 제한된 복귀 재관측: stuck 회복에서 현재 실패 조준을 제외한 graph 대안이 `graph_entry_retreat_exhausted`이고, return 모드/현재 hub 없음/phase 내 미사용/원래 최대3회 recovery 미소진/현재250ms일 때만 phase당1회 새 지역 graph를 만든다. native는 같은 view의 source와 실제 이번 mapping source가 일치하고 mapping_current/Stop 해제를 요구한다. 실패 좌표 제외·전체 시한·버프 시한·현재 hub/terminal 근거를 보존하고, old graph/조향만 해제한다. 이 화면에서는 입력을 보내지 않고 `route_graph_reacquire_hold` 후 다음 새 HUD/현재 바닥/Stop·포커스·조준 검사를 다시 통과해야 이동한다. 재관측은 도착이나 성공을 승인하지 않으며 대안이 여전히 없거나 다시 막히면 원래 정지 경로를 따른다. 사망·용병 미확인·자원·패널·오래된 관측의 예외가 아니다.

R10 뒤 보정은 새 방 횟수를 초기화하지 않는다. 북쪽 탐색의 현재 바닥 굴곡은 `ArcaneRouteFlow::follows`와 이동 직전150도 보호가 같은 등각 투영(y×2) 각도를 사용한다. raw 화면 각도와 섞지 않으며150도 이상 역방향·기존 source250ms/포커스/Stop/바닥/재확인 보호는 유지한다. R10 실제 벡터[-692,-39]는 raw150.2도지만 보정128.6도로 현재 굴곡에 해당하며, 진짜 반대 벡터는 계속 거부한다. 새 맵 전체를 외워서 역방향을 무조건 허용하지 않는다.

native 버프 진단은 같은 저장 worker에 각 단계의 frame 소유권을 즉시 넘긴다. 기존 Vec trace와 callback은 동시에 지정할 수 없고16단계 제한/현재 HUD·장비 균형·시간/오류 의미를 보존한다. 버프 파일은 원래 이름, nav 파일은 phase prefix를 사용한다. 합계는 `diagnostic_evidence_stream`이 소유한다. native의 최근 회전 참고는8장에서2장으로 줄이고 종료 시 시작/마지막 이미지를 먼저 제출한다. 재생/모의는 원래8장과 순서를 유지한다. queue 자체2대기+1저장 외에 현재 interval의 first/last/motion과 이 두 회전·전용 encounter/비상 증거 등 별도 bounded owner가 있으므로 전체 앱3장 상한이라고 주장하지 않는다.

반경 내부/경계/바깥·잘못된 설정·호버 pending 중 이동/범위 이탈·보스/정지 방어 범위를 검사한다. graph 비국소화의 왕복 후보와 현재 바닥 굴곡·재국소화·복귀 짧은 출구를 재생/가짜 입력으로 검증한다. fmt/check/Clippy와 관련 release 검사/링크 뒤 Flash/지옥/정상 새 방3회부터 시작한다. 각 실패는 기록하고 코드 복귀 후 다음 번호를 시작하며 복구는3회 분모에서 뺀다. 안전 종료/사망/사용자 개입은 즉시 구분한다.3회 검토 후 필요한 변경과 다음3회를 이어간다. 북쪽10연속 전에는 남쪽 성공을 주장하지 않는다.
